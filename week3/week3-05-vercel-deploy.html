WEEK 3 · STEP 5 — 배포: 검색기에서 챗봇까지

내 PC의 검색기를 세상에 —
배포하고, RAG 챗봇으로 승격하기

③에서 만든 유사 판례 검색엔진은 내 PC가 켜져 있을 때, 나만 쓸 수 있었습니다. 이 실습은 두 부로 갑니다. Part A — 그 백엔드를 클라우드(Vercel)로 옮겨 URL 하나로 누구에게나 공유되는 서비스로 만듭니다. Part B — 배포된 검색기를 ④에서 배운 RAG로 승격해, 근거 판례를 달아 답변하는 판결문 챗봇까지 완성합니다. 비밀은 서버에, 환경변수로 — 이 원칙을 오늘 처음 손으로 실행합니다.

1

Part A · 지금까지의 한계 — 왜 나만 쓸 수 있었나

③에서 만든 검색기의 구조를 다시 봅시다. 브라우저(프런트엔드)는 판결문을 검색할 때마다 내 PC에서 도는 파이썬 로컬 서버에 물어봤습니다.

브라우저검색어 입력 → 내 PC의 로컬 서버OpenRouter 키 보관 · 임베딩 계산 → OpenRouter API임베딩 모델 → 유사 판례 결과

이 구조가 필요했던 이유는 하나였습니다: OpenRouter API 키를 브라우저에 둘 수 없어서입니다. 브라우저에 넣은 값은 화면을 여는 누구나 개발자도구로 꺼내 볼 수 있고, 꺼낸 키로 내 계정 요금이 청구됩니다. 그래서 키를 든 중개인(백엔드)이 필요했습니다.

그런데 그 중개인이 내 PC에 살고 있으니 문제가 생깁니다:

🔌
PC를 끄면 서비스도 꺼짐노트북을 덮는 순간 검색기는 세상에서 사라집니다.
🏠
주소가 localhost127.0.0.1은 "내 컴퓨터 자신"이라는 뜻. 남에게 보내줄 수 있는 주소가 아닙니다.
👤
동시 사용자 = 나 혼자친구·동료·수강생에게 "이거 써봐"라고 말할 방법이 없습니다.
Part A의 목표 이 중개인을 내 PC에서 클라우드로 이사시킵니다. 그러면 (1) 24시간 켜져 있고 (2) 전 세계에서 접속 가능한 진짜 URL이 생기고 (3) 여러 명이 동시에 써도 됩니다. 코드는 거의 그대로입니다 — 사는 곳만 바뀝니다.
2

Part A · Vercel과 서버리스 — push하면 서버가 된다

Vercel은 GitHub 저장소를 연결하면 자동으로 배포해 주는 클라우드 서비스입니다. 1주차의 GitHub Pages와 비교하면 위치가 명확해집니다.

GitHub Pages (1주차)Vercel (오늘)
올릴 수 있는 것정적 파일 (HTML·CSS·JS)정적 파일 + 서버에서 도는 코드
비밀 보관불가능 — 모든 파일이 공개가능 — 환경변수에 저장
배포 방법저장소에 push저장소에 push (동일!)
무료 범위공개 저장소면 무제한Hobby 플랜 — 개인 프로젝트에 충분
주소아이디.github.io/저장소프로젝트명.vercel.app

중요한 것은 작업 흐름이 1주차와 똑같다는 점입니다. 코드를 GitHub에 push하면 Vercel이 알아서 감지하고 새 버전을 배포합니다. "서버 관리"라는 일이 통째로 사라진 것 — 이것이 요즘 배포 방식(서버리스)의 핵심입니다.

이름에 속지 마세요. "서버리스(serverless)"는 서버가 없다는 뜻이 아니라, 서버를 내가 관리하지 않는다는 뜻입니다. 서버는 Vercel의 데이터센터에 있고, 나는 코드만 올립니다.

서버리스 함수 — 로컬 서버의 클라우드 버전

Vercel에서 백엔드는 서버리스 함수(serverless function)라는 형태로 돕니다. 저장소의 api/ 폴더에 파일을 넣으면, 그 파일 하나하나가 주소/api/파일명으로 호출되는 백엔드가 됩니다.

③ — 내 PC의 로컬 서버

  • 터미널에서 uvicorn main:app으로 직접 실행
  • 내가 실행해 둔 동안만 살아 있음
  • 주소: localhost:8000/search
  • 키: 내 PC의 openrouterkey.txt/.env 파일

오늘 — Vercel 서버리스 함수

  • api/search.py 파일을 저장소에 넣으면 끝
  • 요청이 올 때만 깨어나 실행되고 다시 잠듦
  • 주소: 내앱.vercel.app/api/search
  • 키: Vercel의 환경변수 설정 화면

"요청이 올 때만 깨어난다"는 점이 무료로 운영 가능한 이유입니다. 24시간 컴퓨터를 빌리는 게 아니라, 실행된 순간만큼만 자원을 쓰기 때문입니다. 개인 프로젝트나 MVP 수준의 트래픽이면 무료 한도를 넘기 어렵습니다.

우리가 할 일은 "요청"뿐 로컬 서버 코드를 서버리스 함수 형식으로 고치는 일은 AI에게 맡깁니다. 우리가 알아야 할 것은 구조 — "로컬 서버가 하던 일을 api/ 폴더의 함수가 대신한다" — 입니다. §3의 프롬프트가 이 변환을 요청합니다.
3

Part A · 실습 — 검색기 배포 4단계

여기서부터는 직접 합니다. 15분 안에 배포 URL까지 갑니다. 막히면 손을 드세요.

1 Vercel 가입 — GitHub 계정으로

vercel.com → Sign Up. 가입 과정에서 몇 가지를 묻는데, 이렇게 답하면 됩니다:

  • 플랜 선택 → Hobby. 개인 프로젝트용 무료 플랜으로, 이번 실습 전부에 충분합니다.
  • 이름 → 자유롭게. 화면 표시용입니다.
  • 가입 방법 → Continue with GitHub. 새 비밀번호를 만들 것 없이 ①에서 로그인해 둔 GitHub 계정으로 들어갑니다. GitHub이 Vercel을 승인하겠느냐고 물으면 Authorize를 누르세요 — 로그인 연결 승인입니다.
  • 이메일 인증을 요구하면 → 메일함에 온 인증 메일의 코드를 입력하거나 확인 링크를 누릅니다 (무료 계정 부정 사용을 막기 위한 절차입니다).

가입을 마치고 나오는 첫 화면에서 한 가지를 더 해 둡니다 — Import Git Repository 칸의 Install GitHub을 클릭하세요. GitHub 화면으로 넘어가면 설치할 계정을 고르고, 저장소 접근 범위(전체 또는 검색기 저장소만)를 선택한 뒤 Install을 누릅니다. 이 연동을 해야 3단계의 Import 화면에 내 저장소 목록이 나타납니다.

2 코드 변환 — 지시하면, AI가 먼저 문제를 제기한다

③의 프로젝트 폴더를 연 뒤 "Vercel에 배포할 수 있게 바꿔 달라"고 지시합니다. 그런데 실제로 시켜 보니 Claude Code는 바로 바꾸지 않고 문제 두 가지를 먼저 제기했습니다:

첫째, 판결문 347건이 인터넷에 공개됩니다. GitHub 저장소를 비공개로 한 이유가 바로 이것인데(DECISIONS.md D-12), Vercel에 올리면 URL을 아는 누구나 볼 수 있습니다. 무료 플랜에는 비밀번호 보호 기능이 없습니다(유료 기능).

둘째, API 키가 무방비로 노출된 것과 같아집니다. 공개 URL 뒤에 키가 있으면 누구나 무제한으로 질문을 던질 수 있고, 그 비용은 전부 선생님 OpenRouter 잔액에서 나갑니다. 질문당 1.2원이라 우습게 보이지만 자동화된 요청 몇 만 건이면 금방입니다.

둘 다 맞는 지적이고, 둘 다 기술 문제가 아니라 내가 내릴 결정입니다. 실제로 이렇게 답해서 진행시켰습니다:

💬 실제 지시 — 위험을 알고 내린 결정 
현재 웹앱을 vercel에 배포할 수 있도록 바꿔줘. 판결문 공개되어도 무방함.
openrouter credit 부담할 것이야. 나중에 인증 기능 추가할 예정이라서
지금은 상관 없음.

③에서 남긴 기록(DECISIONS.md의 D-12 "저장소 비공개" 결정)을 AI가 스스로 찾아 새 지시와의 충돌을 지적했습니다 — 문서화는 이렇게 되돌아옵니다. 위험을 들은 뒤 감수 여부를 정하는 것은 내 몫이고, 그 결정(공개 무방 · 비용 부담 · 인증은 ⑦에서)도 대화에 기록으로 남았습니다. 이 변환에서 키를 openrouterkey.txt 파일에서 읽던 방식은 환경변수에서 읽는 방식으로 바뀌었습니다 — 왜 그래야 하는지는 §4에서 짚습니다.

고치면 다시 배포된다 — push가 곧 배포

이제부터는 Claude Code에서 코드를 수정해 GitHub에 push하면, Vercel이 알림을 받아 자동으로 새 버전을 배포합니다. 손으로 할 일이 없습니다. 배포가 어떻게 되고 있는지는 Vercel 대시보드의 Deployments 화면에서 봅니다 — 실제 이 프로젝트의 화면입니다:

행 하나가 배포 한 번입니다. 이름은 커밋 메시지 그대로라서, 이 세 줄만 읽어도 무슨 일이 있었는지 보입니다 — 배포 준비, 차단 문제 해결, 배포본에서 판결문을 못 찾던 버그 수정. 파란 Production 배지가 지금 서비스 중인 버전이고, 커밋 번호(2b81927)로 어느 코드가 올라가 있는지 GitHub과 맞춰볼 수 있습니다.

Ready 21s — "빌드"가 하는 일 push가 감지되면 Vercel은 배포 전에 빌드(build)부터 합니다: 새 코드를 내려받고 → requirements.txt에 적힌 라이브러리를 설치하고 → 서버리스 함수와 화면 파일을 실행 가능한 꾸러미로 조립한 뒤 → 자기 서버에 올립니다. "Ready 21s"의 21초가 이 조립 시간입니다. 빌드가 실패하면 이전 버전이 그대로 서비스됩니다 — 교체는 성공한 빌드만 하므로, 고치다 실수해도 사이트가 죽지는 않습니다.
4

Part A · 핵심 — API 키는 환경변수에

방금 한 일 중 가장 중요한 것은 4단계의 환경변수입니다. "비밀은 코드가 아니라 서버에" — 이 원칙이 처음 실물이 된 순간이므로 정확히 짚고 갑니다.

환경변수코드 바깥, 서버의 설정 공간에 저장하는 이름=값 쌍. 코드는 "OPENROUTER_API_KEY라는 이름의 값을 읽어라"라고만 쓰여 있고, 실제 값은 Vercel 설정 화면에만 존재합니다.
왜 코드에 안 넣나코드는 GitHub에 올라갑니다. 공개 저장소라면 전 세계가, 비공개라도 저장소 접근자 전원이 키를 봅니다. 실제로 GitHub에 노출된 키를 자동으로 긁어 도용하는 봇이 상시 돌고 있습니다.
왜 브라우저에 안 넣나프런트엔드 JS에 넣은 값은 개발자도구 → Network/Sources에서 누구나 볼 수 있습니다. "숨긴" 것처럼 보여도 브라우저에 전달된 순간 공개된 것입니다.
브라우저키 없음 · 검색어만 보냄 → Vercel 서버리스 함수환경변수에서 키를 읽어 대신 호출 → OpenRouter API → 결과만 브라우저로
이번 주의 공식 비밀은 서버에, 환경변수로. 오늘은 OpenRouter 키였습니다. ⑦에서 이메일 인증을 만들 때는 Gmail 앱 비밀번호가 정확히 같은 자리에 들어가고, 4주차에 구글 시트를 연동할 때는 서비스 계정 키가 또 같은 자리에 들어갑니다. 자리만 기억하면 새로운 것이 없습니다.
5

Part B · 승격 — 검색기에서 RAG 챗봇으로

배포된 검색기는 비슷한 판례 목록을 돌려줍니다. ④에서 봤듯, 그 위에 LLM을 얹으면 근거가 달린 답변을 쓰는 RAG 챗봇이 됩니다. 원리는 ④의 챗봇과 완전히 같고, 다른 것은 LLM이 어디서 도는가뿐입니다.

④ — 내 PC의 RAG

  • 로컬 백엔드가 검색 + LLM 호출 담당
  • 내 PC가 켜져 있어야, 나만 사용
  • 키는 내 PC의 키 파일

오늘 — API 방식 (서버리스)

  • 서버리스 함수가 임베딩·답변 생성 모두 OpenRouter API 호출로 처리
  • 내 PC 꺼도 24시간, URL 아는 누구나 사용
  • 키는 Vercel 환경변수 — §4의 공식 그대로
이용자질문 입력 → /api/chat임베딩 → 유사 판례 검색
→ LLM API로 답변 생성 → 답변 + 근거 판례브라우저에 표시

서버리스 환경에는 무거운 모델을 올릴 수 없고 올릴 필요도 없습니다. 임베딩도 답변 생성도 API 호출 한 번이면 되기 때문입니다. 비용 감각도 2주차에 익힌 그대로입니다 — 질문 1건당 임베딩 호출 1회 + LLM 호출 1회, 수업 규모의 문답 수백 건이면 몇십 센트 수준입니다.

모델 선택도 프롬프트로: OpenRouter는 모델을 문자열 하나로 바꿉니다. 답변 품질이 아쉬우면 "모델을 ○○로 바꿔줘", 비용이 아쉬우면 "더 저렴한 모델로 바꿔줘"라고 요청하면 됩니다. 2주차에 모델을 고르던 방식 그대로입니다.

Part B · 실습 — 챗봇 기능 추가와 재배포

Part A에서 배포한 검색기 폴더를 Claude Code로 열고 아래 프롬프트를 실행합니다. 새 계정도 새 키도 필요 없습니다 — 있는 재료의 조립입니다.

💬 프롬프트 — RAG 챗봇 승격 
이 판례 검색기 웹앱을 RAG 챗봇으로 승격해줘.
Vercel에 배포되어 있는 프로젝트야.

구성:
1. /api/chat : 질문을 받으면 (a) 기존 검색 로직으로 유사 판례 상위 3건을
   찾고, (b) 그 판례들을 근거로 OpenRouter의 LLM API를 호출해 답변을
   생성해서, (c) 답변과 근거 판례 목록을 함께 반환해줘.
   답변에는 "이 답변은 참고용이며 법률 자문이 아닙니다" 문구를 포함해줘.
2. 프런트엔드: 채팅 형태 화면. 답변 아래에 근거 판례 3건을 접을 수 있는
   목록으로 표시. 기존 검색 화면도 남겨두고 서로 오갈 수 있게 해줘.
3. 문답 기록: 답변이 나갈 때마다 시각·질문·답변 요약(200자 이내)을
   서버 로그로 남겨줘. Vercel 대시보드의 Logs 화면에서 확인할 거야.
4. 챗봇 화면에는 "질문과 답변이 서비스 개선을 위해 기록됩니다" 안내
   문구를 작게 추가해줘.
5. LLM은 기존 OPENROUTER_API_KEY 환경변수를 사용해. 키를 코드에 넣지 마.
6. 로컬 확인 방법(vercel dev)과 .env.local 작성법을 알려주고,
   .gitignore에 .env.local을 반드시 포함해줘.
7. 파일 변경까지만 하고 git commit/push는 하지 마.
1 로컬에서 확인

AI가 알려준 대로 .env.local에 OpenRouter 키를 넣고 vercel dev로 로컬 실행 → 질문을 두어 개 던져 봅니다("직장 내 괴롭힘으로 인정된 사례는?") → 답변에 근거 판례 3건이 달리는지 확인합니다. .env.local은 내 PC 전용이며 .gitignore 덕에 GitHub로 올라가지 않습니다.

2 push → 자동 재배포

변경 파일을 검토한 뒤 commit·push. .env.local과 키 파일이 목록에 없는지 push 전에 한 번 더 확인하세요. push하면 Vercel이 자동으로 새 버전을 배포합니다 — §3에서 확인한 그 흐름이고, 환경변수는 이미 등록되어 있으므로 추가 설정이 없습니다.

3 폰으로 최종 확인

내 폰에서 *.vercel.app 챗봇을 열어 질문해 봅니다. 근거 판례가 달린 답변이 오면 — 완성입니다. Vercel 대시보드의 Logs 화면에 방금의 문답이 기록된 것도 확인하세요.

막혔을 때 확인 순서 ① 환경변수 이름 철자가 코드와 일치하는가 → ② 답변만 안 나오면 OpenRouter 잔액을 확인 → ③ 그래도 안 되면 Vercel 프로젝트의 Logs 화면을 복사해 AI에게 "이 에러 원인 찾아줘".

Part B · 라이브 데모 — 기록은 자산이자 책임

이제 강사의 챗봇 주소가 화면에 공개됩니다. 전원이 접속해, 궁금한 사건을 자유롭게 질문해 보세요. 옆에는 Vercel의 Logs 화면이 뜹니다 — 여러분이 질문할 때마다 문답 기록이 실시간으로 흘러갑니다.

이 장면의 의미 수십 명이 동시에 질문하고 있지만 서비스는 멀쩡합니다 — 모든 요청이 키를 든 서버리스 함수 한 곳을 거치고, Vercel이 함수를 필요한 만큼 깨우기 때문입니다. 이용자 누구도 API 키에는 접근하지 못하고, 서버가 허용한 동작(질문)만 열려 있습니다. 이것이 백엔드가 "문지기" 역할을 한다는 말의 실체입니다.

그리고 지금 쌓이는 문답 기록은 그 자체로 "사람들이 판례에 대해 무엇을 궁금해하는가"라는 새 데이터입니다:

  • 자산 — 무엇을 자주 묻나, 근거 판례가 빈약했던(=데이터가 약한) 주제는 무엇인가. 다음 개선의 방향이 기록에서 나옵니다
  • 책임 — 질문에는 이용자의 관심사, 때로는 민감한 사정이 담깁니다(법률 질문이라면 더욱). 그래서 프롬프트에 기록 안내 문구와 "법률 자문이 아님" 고지를 넣었습니다 — 필요한 것만 수집하고, 수집한다는 사실을 알리는 원칙의 실전입니다. 이용자 신원은 수집하지 않고, 목적이 끝난 기록은 지웁니다
기록의 완성은 4주차에 — 지금은 Vercel Logs에 흘러가는 기록이라 며칠 지나면 사라지고, 표로 모아 보기도 어렵습니다. 4주차에 구글 시트를 데이터베이스로 연동해, 문답 이력이 시트에 행으로 영구히 쌓이고 관리용 현황 페이지로 읽는 것까지 완성합니다.

확인 체크리스트

  • 내 챗봇의 *.vercel.app URL이 있고, 다른 사람 기기에서도 열린다
  • OpenRouter 키가 코드 어디에도 없고, Vercel 환경변수에만 있다
  • GitHub에 push하면 Vercel이 자동으로 재배포한다는 것을 확인했다
  • "서버리스 = 서버를 내가 관리하지 않음"을 한 문장으로 설명할 수 있다
  • 질문하면 근거 판례 3건이 달린 답변이 오고, 문답이 Logs에 기록된다
이어지는 실습 ⑦ — 문 달기지금 이 챗봇은 URL만 알면 누구나 들어옵니다. ⑦에서 이메일 인증코드로 챗봇에 문을 달아, 허용된 사람만 들어오게 만듭니다.
자율 심화배포 URL에 1주차의 Cloudflare 커스텀 도메인을 연결해 보세요(Vercel 프로젝트 Settings → Domains). 또는 판결문 대신 내 데이터(리뷰·논문 초록·업무 문서)로 같은 파이프라인을 반복해 보세요.
