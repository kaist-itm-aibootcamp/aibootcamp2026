WEEK 3 · STEP 1 — Claude Code 온보딩

Claude Code 시작하기 —
폴더를 열고, 깃헙 레포를 만든다

2주차의 수집·임베딩·지도는 모두 Cowork에서 했습니다. 이번 주는 검색 서버를 내 PC에서 켜고, 코드를 파일로 쌓고, 그것을 깃헙에 올려 배포까지 갑니다 — 2주차 1강에서 설치해 둔 데스크톱 앱의 Code가 이번 주의 주력입니다. 오늘은 그 준비를 끝냅니다: 필요한 도구를 설치하고, 작업 폴더를 열고, 깃헙 레포를 만들어 둡니다.

1

이번 주는 Claude Code — 오늘 준비할 것

Cowork는 클라우드에서 일하고 결과를 폴더로 내려줬습니다. Claude Code는 내 PC에서 직접 파일을 만들고 프로그램을 실행합니다 — 서버를 켜 두는 일(③), 깃헙에 올려 배포하는 일(⑤)이 전부 여기서 이루어집니다.

git·gh 설치§2 · 터미널에서→ gh 로그인§3 · 브라우저 연동→ 폴더 열기§4 · Claude Code→ 깃헙 레포 생성§5 · 지시 한 번→ 권한 설정§6
2

준비 ① — 터미널에서 git·gh·파이썬 설치하기

도구 세 개를 설치합니다. 명령 입력이 처음이어도 괜찮습니다 — 아래 명령을 복사해 붙여넣고 Enter, 그게 전부입니다.

git — 파일의 변경 이력을 기록하는 도구 코드가 바뀔 때마다 "언제 무엇이 어떻게 바뀌었는지"를 기록하고, 그 기록을 깃헙 저장소와 주고받습니다. 1주차에 GitHub Pages에 올렸던 저장소(repository)를 내 PC에서 다루는 도구가 git입니다. Claude Code가 코드를 저장·업로드할 때 내부에서 이것을 씁니다.
gh — 터미널에서 깃헙을 조작하는 GitHub 공식 도구 레포 만들기, 올리기 같은 깃헙 작업을 웹사이트에 들어가지 않고 명령으로 처리합니다. §5에서 Claude Code가 "레포를 만들어줘"라는 지시를 수행할 때 쓰는 손이 바로 gh입니다.
파이썬 — ③의 검색 서버가 이 언어로 돕니다 우리가 파이썬 코드를 직접 쓸 일은 없습니다 — 쓰는 것은 Claude Code의 몫입니다. 다만 그 코드가 돌아갈 컴퓨터에는 파이썬이 설치되어 있어야 합니다.
1 터미널 열기

Windows: 시작 메뉴에서 PowerShell을 검색해 실행합니다. macOS: Spotlight(⌘+Space)에서 터미널을 검색해 실행합니다. 명령을 한 줄씩 입력하는 검은 창이 뜨면 준비된 것입니다.

2 설치 명령 실행
Windows (PowerShell) 
winget install --id Git.Git -e
winget install --id GitHub.cli -e
winget install --id Python.Python.3.13 -e
macOS (터미널) 
git --version
python3 --version
brew install gh

macOS에서 git --version·python3 --version을 쳤을 때 설치 안내 창이 뜨면 그대로 설치하면 됩니다. brew 명령이 없다고 나오면 — Claude Code를 먼저 열고 "gh를 설치해줘"라고 맡기세요. 환경에 맞는 방법으로 안내해 줍니다.

3 설치 확인
확인 
git --version
gh --version
python --version

셋 다 버전 번호가 나오면 성공입니다 (macOS는 마지막을 python3 --version으로). Windows에서 명령을 못 찾는다고 나오면 터미널 창을 닫고 새로 연 뒤 다시 시도하세요 — 설치 직후에는 새 창이어야 인식됩니다.

3

준비 ② — gh 로그인: 명령 한 줄이면 브라우저가 뜹니다

gh가 내 깃헙 계정으로 일하려면 로그인이 필요합니다. 터미널에서 아래 한 줄을 실행하면 브라우저가 알아서 열리면서 연동이 됩니다.

로그인 명령 
gh auth login --hostname github.com --git-protocol https --web

실행하면 이런 화면이 지나갑니다 — 질문에 Yes로 답하고, 화면에 뜬 일회용 코드를 복사한 뒤 Enter를 누르면 브라우저가 열립니다. 브라우저에 코드를 붙여넣고 승인하면 끝입니다.

PowerShell
PS C:\claude\no-bullying> gh auth login --hostname github.com --git-protocol https --web
? Authenticate Git with your GitHub credentials? Yes

! First copy your one-time code: 1BC6-A269
Press Enter to open https://github.com/login/device in your browser...
✓ Authentication complete.
- gh config set -h github.com git_protocol https
✓ Configured git protocol
✓ Logged in as kaist-itm-aibootcamp
어느 폴더에서 실행해도 됩니다 — 로그인은 계정 단위라서, 위 화면처럼 프로젝트 폴더 안일 필요는 없습니다. 잘 됐는지는 gh auth status로 언제든 확인할 수 있습니다.
4

Claude Code에 작업 폴더 열기

이번 주 내내 쓸 프로젝트 폴더를 하나 만들고, Claude Code로 엽니다.

1 프로젝트 폴더 만들기 — C:\claude\no-bullying

2주차 폴더(C:\claude) 아래에 no-bullying 폴더를 만들고(macOS는 ~/claude/no-bullying), 저는 2주차 산출물 — 판결문 파일들(rulings/), 임베딩 JSON(embeddings_json/), 요약 목록(rulings_summary.csv) — 을 이 안으로 옮겨 두었습니다. 이번 주 작업에 필요한 파일을 옮겨 두면 됩니다. 직장 내 괴롭힘 판결문 프로젝트라 이름을 no-bullying으로 지었습니다 — 여러분의 프로젝트에 맞는 영문 이름이면 됩니다.

2 Claude Code로 폴더 열기

Claude 데스크톱 앱에서 Code를 고르고, 방금 만든 폴더를 작업 폴더로 엽니다. 2주차에 Cowork로 폴더를 연동했던 것과 같은 감각입니다 — 다른 점은 이제 AI가 이 폴더 안에서 직접 실행까지 한다는 것입니다.

5

첫 지시 — 깃헙 레포 만들기

폴더가 열렸으면 첫 지시를 내립니다. 깃헙 레포는 ⑤(배포)에서 필요해지지만, 지금 만들어 두면 이번 주 작업이 전부 이력으로 남습니다.

💬 첫 프롬프트 
현재 폴더 내용으로 깃헙 레포를 만들어서 작업하려고 해.
깃헙에 no-bullying이라는 레포를 만들어줘.
openrouterkey.txt 같은 비밀 파일은 레포에 올리지 말고.

이 한 번의 지시로 Claude가 알아서 진행합니다 — 폴더를 git 저장소로 초기화하고, 올리지 않을 파일을 정리하고(.gitignore), §3에서 로그인해 둔 gh로 깃헙에 레포를 만들어 업로드까지 합니다. 공개/비공개를 물어보면 비공개(private)로 시작하세요 — 나중에 언제든 공개로 바꿀 수 있습니다.

올리기 전에 — 비밀 파일 확인 깃헙에 올라간 파일은 그 레포를 볼 수 있는 모두가 봅니다. 프롬프트에 비밀 파일 제외를 명시한 이유입니다. 작업이 끝나면 github.com에서 레포를 열어 openrouterkey.txt가 목록에 없는지 직접 확인하세요. 만약 올라갔다면 — 파일만 지우는 것으로는 부족합니다(이력에 남습니다). 그 키를 폐기하고 새로 발급하는 것이 정답입니다(2주차 ④의 "키를 다루는 세 가지 습관").
확인 — 브라우저에서 github.com에 로그인해 내 계정의 no-bullying 레포가 생겼는지, 판결문·임베딩 파일이 들어 있는지 열어 보세요. 여기까지 되면 이번 주 준비는 끝났습니다.
6

권한 설정 — 자동 승인을 얼마나 줄 것인가

방금 §5에서 경험했듯 Claude Code는 명령 실행·파일 변경 전에 승인을 요청합니다. 이 확인을 얼마나 자동화할지는 사용자가 정합니다.

방식동작어울리는 경우
매번 확인실행마다 내용을 읽고 승인처음 쓰는 도구·낯선 폴더·민감한 자료
선택적 허용같은 종류의 작업은 계속 허용반복 작업이 많은 실습 중반부터
자동 승인대부분의 작업을 확인 없이 진행신뢰하는 폴더의 학습·취미 프로젝트

기준은 작업의 목록이 아니라 다루는 자료입니다. 최근의 Claude 데스크톱 앱은 자동 모드가 많이 다듬어져서, 위험한 작업(대량 삭제, 밖으로 보내기 등)은 자동 모드에서도 따로 확인을 요청합니다. 그래서 판단은 이렇게 하면 됩니다:

지금 단계 — 자동 승인을 줘도 됩니다 이번 프로젝트는 학습용이고, 데이터는 공개된 판결문입니다. 잘못돼도 잃을 것이 폴더 하나입니다. 자동 승인을 켜고 속도를 내세요 — 승인 대기가 사라지면 실습 흐름이 훨씬 매끄럽습니다.
7

마무리 체크리스트

  • git(변경 이력 기록)·gh(터미널에서 깃헙 조작)·파이썬(③의 서버 실행용)을 설치하고 버전을 확인했다
  • gh auth login 한 줄로 브라우저가 열리며 계정이 연동된다 — "Logged in as"의 계정명 확인
  • 프로젝트 폴더(C:\claude\no-bullying)에 2주차 산출물을 모아 Claude Code로 열었다
  • 지시 한 번으로 깃헙 레포가 만들어진다 — 비밀 파일 제외를 명시하고, 올라갔는지 직접 확인
  • 승인 수준은 다루는 자료로 정한다 — 이번 학습 프로젝트는 자동 승인을 켜도 된다
다음 강의 — 두 가지 검색 패러다임 (②)도구 준비가 끝났으니 만들 것을 정합니다. 판결문 347건으로 키워드 검색과 임베딩 검색을 직접 비교해 보고, "왜 백엔드가 필요한가"에 도달합니다 — 그 백엔드를 ③에서 이 폴더에 만듭니다.
이번 주의 흐름오늘 만든 레포에 ③의 검색엔진과 ④~⑤의 챗봇 코드가 쌓이고, ⑤에서 이 레포를 Vercel에 연결하는 순간 URL 하나로 세상에 공개됩니다.
