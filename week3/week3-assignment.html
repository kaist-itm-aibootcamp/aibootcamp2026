WEEK 3 · 자율 실습 (선택) — 내가 만들고 싶은 것을, 세상에

내 웹앱 하나를 만들어 Vercel로 배포하기

내가 배포해 보고 싶은 웹앱을 만들어 Vercel에 올려 보세요. 강의에서 다룬 검색엔진이나 RAG 방식 문서 작성기여도 좋고, 전혀 다른 어떤 방식이어도 좋습니다. 성공의 기준은 화려함이 아니라 "실제 URL로 동작하는가" 하나입니다.

1

아이디어 정하기 — 무엇이든, 단 내 것으로

아래는 이번 주 강의의 프롬프트를 재사용할 수 있는 방향들입니다.

방향예시재사용할 강의
검색엔진내 분야 문서(특허·논문·리뷰·규정) 유사 검색기 — 2주차 과제의 특허 임베딩 200건이 있다면 바로 재료가 됩니다③
RAG 질의응답내 자료를 근거로 답하는 챗봇 (사내 규정 안내, 논문 Q&A)④⑤
RAG 방식 문서 작성기"작성 요청"을 받으면 관련 자료를 검색해 근거를 모아 초안을 써 주는 도구 — 질문에 답하는 대신 문서를 생성④⑤ + 2주차 ⑥
완전히 다른 것계산기·시뮬레이터·소개 사이트… 1주차의 정적 웹앱에 서버 기능을 얹은 무엇이든1주차 + ⑤
범위는 작게 — "동작하는 작은 것"이 "거창한 미완성"보다 낫습니다. 기능 하나를 정해 그것만 끝까지 가세요.
2

만들기 — 계획서부터, 문서와 함께

③에서 배운 방식 그대로입니다: 코드보다 계획서를 먼저 받아 검토하고, 완성되면 문서 네 파일을 남깁니다.

1
계획서 왕복
💬 시작 프롬프트 (한 줄 정의를 넣어 시작) 
이런 웹앱을 만들려고 해: [나의 한 줄 정의].
바로 코드를 쓰지 말고, 먼저 계획서를 작성해줘 — 화면 구성, 필요한
API(백엔드 함수), 데이터·파일 구조, 만들 순서. 내가 검토한 뒤 시작하자.
궁금한 점이 있으면 먼저 질문해줘.

계획서에서 이해 안 되는 항목은 그냥 물어보세요 — "왜 이게 필요해?"가 ③에서 배운 검토의 핵심이었습니다.

2
로컬에서 동작 확인

Claude Code와 함께 구현하고 내 PC에서 먼저 돌려 봅니다. API 키가 필요하면 처음부터 환경변수로 — ⑤에서 배운 원칙입니다.

3
문서 남기기

③ §5의 문서화 프롬프트로 PLAN.md · DECISIONS.md · README.md · CLAUDE.md를 만들어 커밋합니다. README의 합격선: 처음 보는 사람이 README만 보고 실행할 수 있는가.

3

배포 — Vercel에 올려 URL 받기

⑤의 배포 절차를 내 앱에 적용합니다. GitHub에 올리고 → Vercel에 연결하고 → 환경변수를 넣고 → 배포.

1
배포

⑤ 자료의 배포 4단계를 그대로 따라갑니다. 배포 후 다른 기기(폰)로 접속해 확인하고, 코드 안에 키가 0건인지 검사하세요.

2
(선택) 문 달기

나만 쓸 앱이면 ⑦ §5의 비밀번호 잠금(해시 + 환경변수)으로 충분합니다. 여럿을 명단으로 들이려면 ⑦의 이메일 인증코드를 붙여 보세요.

배포 전 3초 점검 ① 코드·GitHub에 API 키가 없는가 ② 수집한 데이터에 개인정보가 없는가 ③ 공개해도 되는 데이터인가.
4

마무리

배포된 URL을 다른 기기(폰)에서 열어 보는 순간이 이 실습의 결승선입니다.

막히면막힌 화면을 AI에게 보여주고 "여기서 왜 안 되는 거야?"라고 물어보세요. 계획서 단계로 돌아가 범위를 줄이는 것도 좋은 선택입니다 — 기능 하나를 끝까지.
4주차와의 연결배포한 앱에 4주차의 구글 시트 연동(기록·대시보드)과 루틴 자동화를 얹으면 완전한 서비스가 됩니다. 만든 앱은 다음 수업에서 자랑해 주셔도 좋습니다.
