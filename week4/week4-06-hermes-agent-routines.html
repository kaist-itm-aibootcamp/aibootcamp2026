WEEK 4 · STEP 6 — 에르메스 에이전트 ②

에르메스 에이전트 ② —
cron 루틴과 진행상황 대시보드

⑤에서 깨운 에이전트에게 이제 반복 업무를 맡깁니다. 3주차 총정리에서 남겨 둔 숙제 — "아무도 안 볼 때는 누가 일하나" — 가 오늘 풀립니다. 정해진 시각에 스스로 일하고 결과를 텔레그램으로 보내는 cron 루틴, 그리고 에이전트를 한눈에 관리하는 대시보드까지. 마지막에는 솔직한 비교도 합니다: 이 일, 사실 Claude로도 됩니다.

1

루틴 — 반복 업무를 에이전트에게

지금까지 만든 것들은 전부 요청이 와야 움직였습니다. 서버리스 함수는 브라우저가 부를 때, 챗봇은 질문이 올 때, 에이전트는 내가 말을 걸 때. 루틴은 그 반대입니다 — 정해진 때에, 사람 없이, 알아서.

cron 표기법 — 시각을 다섯 칸으로 적는 법

예약 시각은 유닉스 전통의 cron 표기법으로 적습니다. 다섯 칸이 각각 분·시·일·월·요일이고, *는 "매번"이라는 뜻입니다.

다섯 칸의 의미
분(0-59) 시(0-23) 일(1-31) 월(1-12) 요일(0-6, 일요일=0)
0 9 * * *
매일 아침 9시 정각
30 18 * * 5
매주 금요일 저녁 6시 30분
0 9 1 * *
매월 1일 아침 9시
셸 cron과의 결정적 차이 — 전통적인 cron은 고정된 명령을 반복합니다(같은 스크립트, 같은 결과 형식). 에르메스의 cron 작업은 에이전트 태스크로 실행됩니다 — 목표(프롬프트)를 주면 매번 판단–실행–해석을 거쳐 일합니다. "뉴스를 요약해줘"라는 같은 목표라도 그날의 뉴스에 맞게 스스로 검색하고 고르고 정리한다는 뜻입니다.
2

실습 — 아침 브리핑 루틴 만들기

매일 아침 9시, 관심 분야 소식을 요약해 텔레그램으로 받아 봅시다. 명령 한 줄입니다.

1 루틴 등록
⌨️ 터미널 
hermes cron create \
  --prompt "AI 업계의 최근 24시간 주요 소식을 조사해서, 한국어로 5줄 요약해줘. 각 항목에 출처 링크를 붙이고, 마지막에 오늘 내가 주목할 한 가지를 골라줘." \
  --schedule "0 9 * * *" \
  --deliver telegram

--prompt가 목표, --schedule이 시각(매일 9시), --deliver가 결과를 받을 통로입니다. 프롬프트는 여러분의 관심사로 바꾸세요 — "우리 업계 규제 동향", "관심 종목 공시", "경쟁사 채용 공고" 무엇이든.

2 등록 확인
⌨️ 터미널 
hermes cron list
hermes cron status

등록된 루틴 목록과 다음 실행 시각, 최근 실행 결과를 확인합니다.

재시작에도 살아남는다 루틴은 에르메스 홈 폴더에 저장되므로 컴퓨터나 에이전트를 재시작해도 유지됩니다. 내일 아침 9시, 아무것도 하지 않아도 텔레그램에 브리핑이 도착합니다 — 3주차의 남은 숙제("요청이 와야 움직인다")가 풀리는 순간입니다.
④와 이어 보기 — 루틴의 프롬프트에 "결과를 구글 시트에 한 행 추가해줘"를 더하면? ③의 서비스 계정 + append 패턴과 오늘의 루틴이 합쳐져, 매일 데이터가 쌓이고 대시보드가 자동 갱신되는 완전 자동 파이프라인이 됩니다. 이번 주 과제의 힌트입니다.
3

대시보드 — 에이전트 관리 화면

터미널 명령이 익숙하지 않아도 괜찮습니다. 에르메스에는 웹 관리 화면이 내장되어 있습니다.

⌨️ 터미널 
hermes dashboard

브라우저에서 대시보드가 열립니다(로컬 설치라면 http://localhost:8000, VPS라면 안내되는 접속 주소). 한 바퀴 둘러보면:

MCP 카탈로그
에이전트에 꽂을 수 있는 MCP 서버 목록 — ②에서 배운 "표준 도구함"이 여기서 에이전트의 도구가 됩니다
자격증명
API 키·토큰 관리 — .env의 내용을 화면에서 관리
게이트웨이 설정
텔레그램 등 메신저 연결과 페어링 상태
메모리 설정
장기 기억(memories/)의 동작 방식 조정
진단
hermes doctor의 화면 버전 — 환경 문제를 한눈에
대시보드는 관리자 화면입니다 — 자격증명·게이트웨이까지 만질 수 있는 화면이므로, VPS에서 외부 접속을 열어 둘 때는 반드시 강한 비밀번호(④에서 만든 계정)로만 접근되게 유지하세요. 로컬 설치라면 localhost 주소라 내 컴퓨터 안에서만 열립니다.
4

사실, Claude로도 됩니다 — 솔직한 비교

여기까지 오면 물어야 할 질문이 있습니다. "이거, 꼭 에르메스여야 하나?" — 아니요. 방금 만든 것의 대부분은 이미 쓰던 Claude에도 있습니다.

오늘 한 일Claude에서는
예약 루틴 (아침 브리핑)Claude의 스케줄 루틴(scheduled tasks) — 정해진 시각에 작업을 실행하고 결과를 받아볼 수 있음
장시간 자율 작업Cowork·Claude Code가 이미 수십 분짜리 작업을 자율 수행 — 2·3주차 내내 경험
절차 저장 (스킬)3주차에 만든 SKILL.md 그대로
도구 연결 (MCP)②에서 켠 커넥터 그대로

그렇다면 자가 호스팅 에이전트가 의미 있어지는 경우는 언제일까요? 네 가지입니다:

🖥️ 내 서버에 24시간 상주

회사 내부망의 컴퓨터, 집의 미니 PC에 두고 그 환경의 파일·시스템을 계속 다뤄야 할 때.

💬 메신저가 접점일 때

팀이 이미 사는 텔레그램·슬랙·디스코드 안에서 에이전트를 부르고 결과를 받아야 할 때.

💰 오픈 모델로 비용 통제

OpenRouter로 저렴한 오픈 모델을 꽂아 대량 반복 작업의 비용을 직접 조절하고 싶을 때.

🔒 데이터 주권

데이터를 내 인프라 밖으로 내보낼 수 없는 규정·계약이 있을 때 — 처리 전 과정이 내 서버 안에서 끝나야 할 때.

솔직한 결론 실무적으로는 Claude만으로 충분한 경우가 많습니다. 관리 부담(설치·업데이트·보안·키 관리)이 전부 내 몫이 되는 것이 자가 호스팅의 대가이기 때문입니다. 오늘 에르메스를 배운 가치는 "갈아타라"가 아니라 선택지를 아는 것입니다 — 위의 네 경우에 해당하면 자가 호스팅, 아니면 관리형(Claude). 이 판단 기준은 ⑦의 판단표에 마지막 행으로 들어갑니다.
5

안전 수칙 재확인 — 루틴은 무인 실행이다

루틴은 내가 안 보는 시간에 도는 실행입니다. ①의 안전장치가 가장 필요한 순간이 바로 지금입니다.

1

페어링 목록을 정기 점검. 결과가 배달되는 통로(텔레그램)에 승인된 사람이 나뿐인지 확인 — 통로가 곧 3요소의 ③(외부 통신)입니다.

2

terminal backend는 docker. 루틴이 실수로(혹은 속아서) 파괴적 명령을 만들어도 컨테이너 안에서 끝나게 — ①의 "속아도 막히는 구조"를 무인 시간에도 유지합니다.

3

루틴이 읽는 것은 전부 "남이 쓴 글". 뉴스·웹페이지를 매일 읽는 루틴은 3요소의 ②(불신 콘텐츠)에 매일 노출됩니다. 루틴의 목표를 "조사·요약·전달"로 한정하고, 파일 삭제·설정 변경 같은 능력과 한 루틴에 섞지 마세요.

4

logs/와 cron status를 아침 브리핑처럼. 무인 실행일수록 사후 확인이 안전장치입니다 — 자율은 무감독이 아니다, 마지막으로 한 번 더.

6

마무리

  • 루틴 = 목표 + cron 시각 + 전달 통로 — 고정 스크립트가 아니라 매번 판단하는 에이전트 태스크
  • 재시작에도 유지, 결과는 메신저로 — "요청이 와야 움직인다"의 한계를 넘었다
  • 대시보드(hermes dashboard) = MCP·자격증명·게이트웨이·메모리·진단의 관리 화면
  • 솔직한 비교: 스케줄 루틴·자율 작업·스킬·MCP는 Claude에도 있다 — 자가 호스팅의 가치는 상주·메신저·비용·데이터 주권
  • 무인 실행일수록 안전장치: 페어링 점검 · docker · 능력 분리 · 로그 확인
