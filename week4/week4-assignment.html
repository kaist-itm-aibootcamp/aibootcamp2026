WEEK 4 · 자율 실습 (선택) — 4주의 기술을 한 화면에

내 포트폴리오 수익률 앱 만들기

제출도 정답도 없습니다 — 해 보고 싶은 분들을 위한 상세 안내입니다. 내 투자 포트폴리오(가상이어도 됩니다)를 구글 드라이브의 시트에 올리고, 앱이 주기적으로 현재가를 수집해 DB에 쌓은 뒤, 그 기록으로 수익률과 자산 추이 그래프를 보여주는 앱을 만듭니다. 마지막으로 비밀번호를 입력해야 들어올 수 있는 잠금까지 — 시트 연동(④), 루틴 수집(⑥의 원리), 배포(3주차 ⑤), 비밀번호 해시(3주차 ⑥ §6)를 한 번에 복습하게 됩니다.

1

구글 시트에 포트폴리오 원장 만들기

구글 드라이브에서 새 스프레드시트를 만들어 보유 내역(원장)을 적습니다. 실제 계좌가 부담스러우면 가상 포트폴리오로 하세요 — 목적은 연동과 자동화이지 투자가 아닙니다.

탭 1 — portfolio (내가 적는 원장):

종목명티커수량매수단가
삼성전자005930.KS1071,000
AppleAAPL3185.2
… 5종목 이상 권장

탭 2 — prices (앱이 채우는 가격 기록, 지금은 머리글만):

수집일시티커가격
비워 두세요 — §2의 수집 함수가 매일 여기에 한 줄씩 쌓습니다
왜 현재가 열이 원장에 없을까 — 현재가는 계속 변하는 값이라 원장에 적는 순간 낡습니다. 그래서 앱이 주기적으로 시세를 수집해 prices 탭에 기록으로 쌓습니다. 기록이 쌓여야 "오늘의 수익률"만이 아니라 "자산 가치가 어떻게 변해 왔는지" 그래프를 그릴 수 있습니다 — 스냅숏이 아니라 시계열이 필요한 이유입니다.
2

주기 수집 백엔드 — 앱이 시세를 모아 DB에 쌓는다

이 실습의 심장입니다. 구조는 세 부분 — 수집 함수(시세를 조회해 기록), 스케줄(매일 자동 실행), 화면(기록을 읽어 수익률·그래프 표시). ③에서 배운 서비스 계정 읽기/쓰기가 그대로 쓰입니다.

1
서비스 계정 연결

④ §3~4의 절차대로 서비스 계정을 발급하고 시트에 편집자로 초대합니다. 시트는 비공개인 채로 앱만 읽고 쓸 수 있게 됩니다 — 포트폴리오는 민감 정보이므로 "웹에 게시"가 아니라 처음부터 이 방식으로 갑니다.

2
수집 함수 + 스케줄 + 화면 만들기
💬 Claude Code 프롬프트 
포트폴리오 수익률 앱을 만들자. 먼저 계획서부터 보여줘.

1. 데이터: 비공개 구글 시트를 서비스 계정으로 읽고 쓴다.
   - portfolio 탭(원장): 종목명, 티커, 수량, 매수단가 — 읽기만
   - prices 탭(가격 기록): 수집일시, 티커, 가격 — 수집 함수가 추가(append)

2. 수집 함수 /api/collect:
   원장의 티커별 현재가를 무료 시세 API에서 조회해
   prices 탭에 한 줄씩 추가한다. 어떤 시세 API를 쓸지 후보와
   장단점을 계획서에서 먼저 제안해줘.

3. 스케줄: 이 함수가 매일 장 마감 후 1회 자동 실행되도록
   Vercel Cron으로 등록한다.

4. 화면:
   - 맨 위: 총 평가금액과 전체 수익률 크게 (최신 가격 기준)
   - 종목별 표: 수량, 매수단가, 현재가, 평가금액, 수익률
   - 아래: prices 기록으로 그린 총 자산 가치 추이 그래프

5. 비밀(서비스 계정 키 등)은 전부 서버 환경변수로. 코드에 넣지 마.

2번처럼 시세 API 선택은 계획서 단계에서 AI가 후보를 제안하게 하세요 — 무료 API는 국가·종목별로 지원이 달라서, 내 포트폴리오 구성에 맞는 것을 골라야 합니다.

3
첫 수집 실행 — 기록이 쌓이는지 확인

배포 전 로컬에서 /api/collect를 직접 한 번 호출해, prices 탭에 오늘 날짜의 행들이 실제로 생기는지 시트를 열어 눈으로 확인합니다. 스케줄 등록 후에는 다음 날 한 줄이 더 쌓였는지 봐야 진짜 완성입니다.

"DB가 왜 구글 시트야?" 맞습니다, 여기서 시트의 prices 탭이 DB 역할을 합니다. 이미 배운 서비스 계정 쓰기로 충분하고, 쌓이는 기록을 눈으로 열어 볼 수 있어 학습용으로 최적입니다. 기록이 수만 행으로 커지면 그때 진짜 DB(Postgres 등)로 옮기면 됩니다 — 3주차 검색엔진에서 "소규모는 전수 계산, 대규모는 전용 DB"라고 했던 것과 같은 판단입니다.
그래프가 하루 만에 안 예뻐도 정상 — 추이 그래프는 기록이 쌓여야 선이 됩니다. 첫날은 점 하나입니다. 수집이 매일 도는 것을 확인했다면 완성이고, 일주일 뒤에 다시 열어 보세요.
3

비밀번호 잠금 걸고 배포하기

포트폴리오는 민감한 개인 정보입니다. 3주차 ⑥ §6에서 배운 지름길 — 비밀번호를 단방향 해시해 환경변수에 두는 방식 — 그대로 문을 답니다.

1
해시 만들기 → 환경변수로

비밀번호를 SHA-256으로 해시하는 스크립트를 실행해(3주차 ⑥ §6 프롬프트 재사용) 해시값을 얻고, Vercel 환경변수 PASSWORD_HASH에 넣습니다.

2
입구 달기 + 배포

"입력값을 해시해 PASSWORD_HASH와 비교, 일치하면 세션 발급, 세션 없으면 화면과 API 모두 차단" — ⑥ §6의 프롬프트 그대로입니다. 배포 후 시크릿 창에서 열어 비밀번호 없이는 안 보이는지, 틀린 비밀번호가 거부되는지 확인하세요.

점검 세 가지 ① 비밀번호 없이 API 주소를 직접 열어도 데이터가 안 나오는가 (단, /api/collect는 Vercel Cron이 부를 수 있어야 하니 세션 대신 별도 시크릿으로 보호 — 계획서에서 AI에게 처리 방법을 물어보세요) ② 코드·GitHub에 서비스 계정 키와 비밀번호가 없는가(환경변수에만) ③ 비밀번호는 길게(문장형) 정했는가.
4

마무리

다음 날 prices 탭에 한 줄이 더 쌓여 있는 것을 확인하는 순간 — 그것이 이 실습의 결승선입니다.

더 가 보고 싶다면 — ⑥에서 배운 루틴으로 "매주 월요일 아침, 수익률 요약을 텔레그램으로"까지 얹으면 4주 전 과정의 완성판입니다.
이 실습에 들어 있는 4주시트 읽기/쓰기 = 데이터 연동(4주차 ④), 매일 도는 수집 = 루틴 자동화(4주차 ⑥의 원리), 앱·배포 = 웹앱과 서버(1·3주차), 해시 잠금 = 보안(3주차), 그리고 이 모든 것을 AI에게 시키는 법(2주차·전 과정). 판결문도 특허도 아닌 내 데이터로 마무리합니다.
수고하셨습니다다음에 자동화하고 싶은 업무가 생기면 — 이제 어디서부터 시작할지 아실 겁니다. 계획서부터, 폴더 하나 안에서, 승인은 읽고.
