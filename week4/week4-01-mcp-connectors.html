WEEK 4 · STEP 1 — 연동이란

연동 — AI를 내 데이터에
연결하는 표준, MCP

3주차까지 AI는 내 폴더 안의 파일로 일했습니다. 이번 주는 AI를 바깥 세계 — 구글 드라이브, 노션 — 와 잇고, 마지막에는 일을 통째로 맡겨 봅니다. 첫 강의인 이 자료는 그 연결의 표준 규격인 MCP가 무엇인지 이해하고, Claude에서 커넥터를 직접 켜서 첫 연결을 체험하는 것까지입니다.

1

문제 — AI는 내 데이터를 모른다

Claude에게 "내 포트폴리오 지금 어떻게 돼 있지?"라고 물으면 답하지 못합니다. 그 데이터는 여러분의 구글 시트에 있고, AI는 거기 접근할 수 없기 때문입니다.

지금까지의 해결책은 파일을 대화에 업로드하는 것이었습니다. 그런데 일일이 올릴 수 없는 상황이 오면 한계가 드러납니다:

🔁
매번 업로드데이터가 바뀔 때마다 사람이 다시 올려야 합니다. "연결"이 아니라 "배달"입니다.
📏
양의 한계시트 수십 장, 메일 수백 통을 일일이 올릴 수는 없습니다. AI가 필요한 부분을 스스로 찾아 읽어야 합니다.
✍️
읽기만 가능업로드로는 AI가 시트에 값을 쓰거나 메일을 보내는 일은 아예 불가능합니다.

필요한 것은 AI가 내 데이터 창고에 스스로 드나들 수 있는 문입니다. 그 문을 만드는 표준이 MCP입니다.

2

MCP — 연결 방법의 표준 규격

MCP(Model Context Protocol)는 AI가 외부 도구·데이터에 연결하는 방법을 하나로 통일한 표준 규약입니다. Anthropic이 2024년 말 공개했고, 지금은 OpenAI·구글을 포함한 업계 전반이 채택한 사실상의 공통 표준이 되었습니다.

표준이 없던 시절의 문제부터 봅시다. 구글 드라이브, 노션, 슬랙은 각자 자기만의 접속 방법(API)을 갖고 있습니다. AI 서비스가 이들과 연결하려면 서비스마다 전용 연결 코드를 따로 만들어야 했습니다. AI가 10개, 도구가 100개면 연결 코드가 최대 1,000벌 필요한 구조입니다.

MCP는 이 사이에 공통 규격을 놓습니다. 도구 쪽은 "MCP 서버" 하나만 만들어 두면 되고, AI 쪽은 MCP를 말할 줄만 알면 어떤 도구든 꽂아 쓸 수 있습니다.

표준 이전 — 제각각 연결

  • AI × 도구 조합마다 전용 연결 코드
  • 도구가 사양을 바꾸면 연결한 쪽 전부 수리
  • 새 도구 지원 = 매번 새 개발

MCP — 하나의 규격

  • 도구는 MCP 서버 1개만 제공
  • MCP를 아는 AI라면 무엇이든 즉시 연결
  • 연결 규격이 같으니 조합이 자유로움
MCP 서버어떤 도구·데이터를 MCP 규격으로 노출하는 프로그램. "이 시트를 읽어라 / 이 행에 써라" 같은 기능 목록을 AI에게 알려주고 실행해 줍니다.
MCP 클라이언트MCP 서버에 접속해 기능을 쓰는 쪽 — Claude 같은 AI 앱입니다.
커넥터Claude 제품에서 MCP 연결을 부르는 이름. 설정에서 커넥터를 켜는 것 = 그 서비스의 MCP 서버에 내 계정으로 접속을 허용하는 것.
3

Claude의 커넥터 = MCP 서버

Claude 설정의 커넥터 목록(Google Drive, Gmail, Notion, Slack…)이 바로 각 서비스의 MCP 서버들입니다. 켜는 순간 무슨 일이 일어나는지 봅시다.

① 커넥터 켜기설정 → Connectors → ② 로그인 화면구글이 직접 띄움 → ③ 권한 동의"Drive 읽기를 허용?" → ④ 연결 완료대화에서 내 파일 사용 가능

주목할 점: ②에서 비밀번호는 구글에게만 입력합니다. Claude는 비밀번호를 받지 않고, 구글이 발급한 권한 증표(토큰)만 받습니다. 증표에는 범위가 적혀 있어(예: "Drive 읽기만") 그 밖의 일은 할 수 없고, 언제든 구글 계정 설정에서 회수할 수 있습니다. 이 방식(OAuth)은 3주차 인증 자료에서 배운 "비밀번호 대신 증표" 원칙과 같은 계열입니다.

커넥터는 계정 단위 연결입니다. 한 번 켜면 이후 모든 대화에서 Claude가 필요할 때 내 드라이브를 검색해 읽을 수 있습니다. 반대로 말하면, 회사 기밀이 담긴 계정을 연결할 때는 어떤 범위를 허용하는지 동의 화면을 반드시 읽어야 합니다.
4

실습 — Drive 커넥터로 내 시트 분석하기

직접 해 봅니다. 5분이면 충분합니다.

1 연습용 시트 만들기

구글 시트를 새로 만들어 간단한 표를 입력합니다. 예: 이번 달 지출 내역(날짜·항목·금액 10행). ②에서 쓸 포트폴리오 표(자산·수량·매입가)를 미리 만들어 봐도 좋습니다. 실제 민감 정보는 넣지 마세요.

2 Google Drive 커넥터 켜기

Claude → 설정(Settings) → Connectors → Google Drive Connect → 구글 로그인 → 권한 동의. 동의 화면에서 어떤 권한을 요구하는지 한 줄씩 읽어 보세요.

3 대화로 분석 요청
💬 프롬프트 
내 구글 드라이브에서 "[시트 제목]" 시트를 찾아 읽고,
어떤 내용인지 요약한 다음 눈에 띄는 점을 알려줘.

파일을 업로드한 적이 없는데 Claude가 시트 내용을 정확히 읽어 옵니다. 시트를 수정하고 같은 질문을 다시 하면 바뀐 내용이 반영됩니다 — 배달이 아니라 연결이기 때문입니다.

방금 일어난 일 Claude(MCP 클라이언트)가 구글의 MCP 서버에 "이 이름의 시트를 찾아 내용을 달라"고 요청했고, 여러분이 허용한 토큰의 범위 안에서 데이터가 대화로 들어왔습니다. 업로드 없이 데이터가 대화로 들어온 첫 경험입니다.
5

커넥터의 한계, 그리고 오늘의 질문

커넥터는 강력하지만, 지금 우리가 만들려는 것 — 남에게 서비스하는 웹앱 — 에는 그대로 쓸 수 없습니다.

커넥터 (지금 한 것)프로그램의 데이터 연동 (②~③에서 다룰 것)
어디서 동작Claude 대화 안내가 배포한 웹앱 안
누가 쓰나연결한 나 자신URL을 아는 누구나
형태질문–답변 (대화형)화면·차트·버튼 (서비스형)
갱신물어볼 때마다자동 (폴링·실시간)
알맞은 용도내 데이터의 분석·정리·탐색여러 사람이 함께 쓰는 도구

즉 커넥터는 "나의 데이터 작업"의 도구입니다. 내가 만든 프로그램이 시트를 직접 읽고 쓰게 하려면 다른 길이 필요합니다 — 그 길로 ②~③에서 포트폴리오 관리기를 만듭니다.

6

마무리 — 이번 주의 지도

오늘 연 것은 문 하나입니다. 이번 주 내내 이 연결 위에 하나의 예제 — 내 포트폴리오 — 를 쌓아 갑니다.

  • ②~③ 구글 시트 — 시트를 데이터베이스 삼아 포트폴리오 관리기를 만들고, 연결 방식을 서비스 계정으로 격상합니다
  • ④ 노션 — 리포트를 노션으로 발행해 사람과 공유하고, 그 데이터로 Claude와 대화합니다
  • ⑤~⑦ 헤르메스 — 안전 원칙을 배우고, 내 에이전트 서버를 세워, 관점이 다른 봇 셋에게 포트폴리오 검토를 맡깁니다. 결정은 나
다음 자료 ② — 시트 읽고 쓰기: 포트폴리오 관리기오늘은 Claude가 시트를 대화에서 읽었습니다. ②에서는 내가 만든 프로그램이 시트를 직접 읽고 쓰게 만듭니다 — 가장 간단한 연결(링크 공유)부터.
커넥터는 계속 쓰입니다④의 노션도, ⑦의 자문단 기록도 커넥터로 연결됩니다. 오늘 배운 "토큰과 권한 범위" 감각이 이번 주 전체의 바탕입니다.
