WEEK 4 · STEP 6 — 헤르메스 설치

내 에이전트 —
헤르메스를 세운다

⑤에서 위험과 안전장치를 배웠습니다. 이 강의는 시연입니다. 설치를 권하는 것이 아니라, 자율 에이전트를 실행하면 무슨 일이 벌어지는지 실제 화면으로 봅니다. 구조(설치 → 모델 연결 → 텔레그램)를 이해한 뒤, "폰에서 시키면 PC에서 실행되는" 장면까지 따라갑니다. 이 에이전트가 ⑦의 투자 자문단을 굴리게 됩니다.

1

헤르메스란 — Claude와 뭐가 다른가

헤르메스(Hermes Agent)는 Nous Research가 공개한 오픈소스(MIT 라이선스) 자율 AI 에이전트입니다. 지금까지 쓰던 Claude와의 차이는 기능이 아니라 존재 방식에 있습니다.

Claude (지금까지)헤르메스 (오늘부터)
어디서 사나Anthropic의 서버 (나는 접속)내 컴퓨터/서버 (자가 호스팅)
언제 사나내가 대화창을 열 때상시 상주(persistent) — 세션이 끝나도 기억 유지
어떻게 부르나앱·웹·터미널메신저 게이트웨이 21개+ — 텔레그램·디스코드·슬랙 등
모델Claude 고정자유 — OpenRouter(200+ 모델)·OpenAI·자체 엔드포인트
확장스킬·MCP·커넥터스킬 자가 생성 + MCP + cron 루틴(⑦)

요약하면: 실행 환경은 내 것, 모델은 골라서 연결하고, 대화 통로는 늘 쓰는 메신저. 이 조합이 "내가 자는 동안 일하는 AI"를 가능하게 합니다. ⑤에서 배웠듯 바로 이 조합(사적 데이터 + 외부 콘텐츠 + 외부 통신)이 치명적 3요소이기도 합니다. 설치 과정 내내 안전장치를 함께 챙기는 이유입니다.

왜 헤르메스인가 — 실행 환경의 자유도

굳이 직접 설치까지 해서 쓰는 이유는 하나입니다. 에이전트의 실행 환경을 내가 원하는 대로 설정할 수 있는 자유도입니다. 지금까지의 Claude는 Anthropic이 정해 둔 환경 안에서 쓰는 완성품입니다. 편하지만 정해진 틀 밖으로는 나갈 수 없습니다. 헤르메스에서는 그 틀을 내가 정합니다:

  • 모델 : 작업마다 골라서 연결합니다. 비싼 추론 모델과 값싼 모델을 용도별로 나눠 쓸 수 있습니다
  • 도구와 기억 : 어떤 스킬과 MCP를 쥐여줄지, 무엇을 기억하게 할지를 내가 구성합니다
  • 시간 : 내가 부를 때만 도는 것이 아니라, 루틴(cron)으로 정해진 시각에 스스로 돌게 합니다
  • 통로 : 내가 매일 쓰는 메신저(텔레그램 등)를 대화 창구로 삼습니다
  • 역할 : 에이전트를 여럿 두고 역할과 성격을 다르게 설정합니다. ⑦의 투자 자문단이 바로 이 자유도로 만들어집니다

자유도의 값은 책임입니다. 환경을 내가 정하는 만큼 안전장치도 내가 챙깁니다. ⑤의 원칙이 이 강의 곳곳에서 실물로 나오는 이유입니다.

2

설치 — 내 컴퓨터에

강사의 시연 환경은 윈도우 PC에 로컬 설치한 헤르메스입니다. 설치 과정 자체는 이 수업에서 다루지 않습니다. 해 보고 싶은 사람은 공식 문서를 따라 하거나 Claude Code에 맡기면 되고, 설치하면 터미널의 hermes 명령으로 실행됩니다.

로컬 설치의 특성 ① 서버 비용 없이 바로 시작하고, 키·대화 기록·데이터가 내 컴퓨터 밖으로 나가지 않습니다 ② 대신 컴퓨터가 켜져 있는 동안만 동작합니다. ⑦에서 루틴을 걸 때는 그 시각에 컴퓨터가 켜져 있어야 합니다 ③ 24시간 상주가 필요해지면 나중에 호스팅 서버로 옮기면 됩니다. ~/.hermes/ 폴더 구조가 같아서 이사가 어렵지 않습니다.

설치 후 내 컴퓨터에 생기는 것 — ~/.hermes/ 홈 폴더

config.yaml
에이전트 설정 — 모델, 게이트웨이, terminal backend 등
.env
API 키 보관소. 3주차 공식("비밀은 환경변수로")의 헤르메스 버전 — §3에서 채웁니다
SOUL.md
에이전트의 성격·말투를 정하는 파일 — 마크다운으로 자유롭게 수정
memories/
세션이 끝나도 유지되는 장기 기억
skills/
스킬 폴더 — 3주차에 만든 SKILL.md 구조와 같은 계열이며, 헤르메스는 스스로 스킬을 만들어 여기 저장하기도 합니다
sessions/ · logs/
대화 기록과 동작 로그 — 에이전트가 무슨 일을 했는지 확인하는 감사 창구
3

OpenRouter 연동 — 모델 연결

헤르메스 자체에 모델은 들어 있지 않아 외부 API로 연결합니다. 2·3주차에 만들어 둔 OpenRouter API 키를 그대로 재사용합니다. 새로 발급할 필요 없습니다.

키는 따로 파일을 만들 필요가 없습니다. 설치 과정에서 OpenRouter 키를 물으면 입력하면 되고, 입력한 키는 ~/.hermes/.env에 저장됩니다.

기본 모델은 config.yaml에서 지정합니다. 시연 환경은 3주차 챗봇과 같은 deepseek-v4-flash입니다:

📄 ~/.hermes/config.yaml 
model:
  provider: "openrouter"
  default: "deepseek/deepseek-v4-flash"

OpenRouter를 통해 200개 이상의 모델을 같은 키로 바꿔 쓸 수 있습니다.

.env는 내 컴퓨터에만 설치 때 입력한 키는 내 컴퓨터의 ~/.hermes/.env에 평문으로 놓입니다. 이 파일을 git에 커밋하거나 메신저로 보내지 말고, 에이전트의 작업 폴더 안에 복사해 두지도 마세요. 울타리 안의 비밀은 보호 대상이 아니라 작업 대상이 됩니다.
4

텔레그램 — 설치 때 함께 연결됩니다

대화 통로도 따로 만들 것이 없습니다. 설치 과정의 안내를 따라가면 텔레그램 봇 연결까지 끝납니다. 이후에는 폰에서 말 거는 것만으로 에이전트가 움직입니다.

⑤의 원칙, 실물 하나 — 페어링 낯선 계정이 봇에게 말을 걸면 바로 대화가 되지 않고 페어링 승인을 거칩니다. 봇 아이디는 사실상 공개 정보라, 승인 절차가 없다면 아무나 내 컴퓨터의 에이전트에게 명령을 보낼 수 있기 때문입니다. ⑤에서 배운 화이트리스트 + HITL이 실물로 구현된 모습입니다.
5

시연 — 폰에서 시키면 PC에서 실행됩니다

이제 핵심 장면입니다. 폰에서 "설치가 잘 되었는지 점검"이라고 보내면, 에이전트가 PC에서 명령을 직접 실행하고 결과를 보고합니다. 실제 화면입니다:

문장 한 줄이 폰을 떠나 PC의 셸 명령 실행으로 이어지고, 어떤 명령을 돌렸는지가 채팅에 투명하게 남습니다. 에이전트가 "도구를 쥔다"는 말의 실물이고, 아무나 페어링되면 안 되는 이유이기도 합니다.

마무리

  • 헤르메스 = 자가 호스팅 · 상시 상주 · 메신저로 부르는 오픈소스(MIT) 에이전트
  • 시연 환경은 내 컴퓨터 로컬 설치. 컴퓨터가 켜져 있는 동안 동작하고, 필요해지면 호스팅으로 옮길 수 있다
  • 모델은 OpenRouter로. 키는 설치 때 입력하며(2·3주차 키 재사용) 기본 모델은 deepseek-v4-flash
  • 텔레그램 연결의 관문은 페어링 코드 — HITL·화이트리스트의 실물
다음 강의 ⑦ — 나의 투자 자문단이 에이전트 위에 관점이 다른 봇 셋을 올립니다. 강세론·약세론·리스크검증 담당이 포트폴리오를 놓고 맞서고, 매일 아침 루틴으로 돌립니다. 결정은 나.
포트폴리오를 물려주기④에서 노션에 매일 쌓이는 포트폴리오 일지를 이 에이전트가 읽게 해 두면, ⑦의 자문단이 내 실제 배분을 검토할 수 있습니다.
