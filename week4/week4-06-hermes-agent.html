WEEK 4 · STEP 6 — 헤르메스 설치

내 에이전트 —
헤르메스를 세운다

⑤에서 위험과 안전장치를 손에 쥐었으니, 이제 자율 에이전트를 직접 설치합니다. 헤르메스(Hermes Agent)는 상주하며 텔레그램으로 말을 걸 수 있는 오픈소스 에이전트입니다. 이번 실습은 내 컴퓨터에 로컬로 설치합니다. 설치 → 두뇌(OpenRouter) 연결 → 텔레그램 연결 → 포트폴리오 연동까지 갑니다. ⑤에서 배운 안전 원칙이 실물로 등장하는 지점들을 놓치지 마세요. 이 에이전트가 ⑦의 투자 위원회를 굴리게 됩니다.

1

헤르메스란 — Claude와 뭐가 다른가

헤르메스(Hermes Agent)는 Nous Research가 공개한 오픈소스(MIT 라이선스) 자율 AI 에이전트입니다. 지금까지 쓰던 Claude와의 차이는 기능이 아니라 존재 방식에 있습니다.

Claude (지금까지)헤르메스 (오늘부터)
어디서 사나Anthropic의 서버 (나는 접속)내 컴퓨터/서버 (자가 호스팅)
언제 사나내가 대화창을 열 때상시 상주(persistent) — 세션이 끝나도 기억 유지
어떻게 부르나앱·웹·터미널메신저 게이트웨이 21개+ — 텔레그램·디스코드·슬랙 등
두뇌(모델)Claude 고정자유 — OpenRouter(200+ 모델)·OpenAI·자체 엔드포인트
확장스킬·MCP·커넥터스킬 자가 생성 + MCP + cron 루틴(⑦)

요약하면: 몸(실행 환경)은 내 것, 두뇌(모델)는 골라 꽂고, 입(대화 통로)은 메신저. 이 조합이 "내가 자는 동안 일하는 AI"를 가능하게 합니다. ⑤에서 배웠듯 바로 이 조합(사적 데이터 + 외부 콘텐츠 + 외부 통신)이 치명적 3요소이기도 합니다. 설치 과정 내내 안전장치를 함께 챙기는 이유입니다.

왜 헤르메스인가 — 실행 환경의 자유도

굳이 직접 설치까지 해서 쓰는 이유는 하나입니다. 에이전트의 실행 환경을 내가 원하는 대로 설정할 수 있는 자유도입니다. 지금까지의 Claude는 Anthropic이 정해 둔 환경 안에서 쓰는 완성품입니다. 편하지만 정해진 틀 밖으로는 나갈 수 없습니다. 헤르메스에서는 그 틀을 내가 정합니다:

  • 두뇌 : 작업마다 모델을 골라 꽂습니다. 비싼 추론 모델과 값싼 모델을 용도별로 나눠 쓸 수 있습니다
  • 도구와 기억 : 어떤 스킬과 MCP를 쥐여줄지, 무엇을 기억하게 할지를 내가 구성합니다
  • 시간 : 내가 부를 때만 도는 것이 아니라, 루틴(cron)으로 정해진 시각에 스스로 돌게 합니다
  • 통로 : 내가 매일 쓰는 메신저(텔레그램 등)를 대화 창구로 삼습니다
  • 역할 : 에이전트를 여럿 두고 역할과 성격을 다르게 설정합니다. ⑦의 투자 위원회가 바로 이 자유도로 만들어집니다

자유도의 값은 책임입니다. 환경을 내가 정하는 만큼 안전장치도 내가 챙깁니다. ⑤의 원칙이 이 강의 곳곳에서 실물로 나오는 이유입니다.

2

설치 — 내 컴퓨터에

헤르메스는 내 컴퓨터에 설치해 돌립니다. 공식 설치 안내를 따라 해도 되고, 이런 일은 Claude Code에 맡기는 것이 이제 익숙한 방법입니다:

💬 프롬프트 
Hermes Agent(Nous Research의 오픈소스 에이전트)를 이 컴퓨터에
설치하려고 해. 공식 문서대로 진행하고, 결정할 게 있으면 물어봐.

설치가 끝나면 터미널에서 hermes 명령으로 실행합니다.

로컬 설치의 특성 ① 서버 비용 없이 바로 시작하고, 키·대화 기록·데이터가 내 컴퓨터 밖으로 나가지 않습니다 ② 대신 컴퓨터가 켜져 있는 동안만 동작합니다. ⑦에서 루틴을 걸 때는 그 시각에 컴퓨터가 켜져 있어야 합니다 ③ 24시간 상주가 필요해지면 나중에 호스팅 서버로 옮기면 됩니다. ~/.hermes/ 폴더 구조가 같아서 이사가 어렵지 않습니다.

설치 후 내 컴퓨터에 생기는 것 — ~/.hermes/ 홈 폴더

config.yaml
에이전트 설정 — 모델, 게이트웨이, terminal backend 등
.env
API 키 보관소. 3주차 공식("비밀은 환경변수로")의 헤르메스 버전 — §3에서 채웁니다
SOUL.md
에이전트의 성격·말투를 정하는 파일 — 마크다운으로 자유롭게 수정
memories/
세션이 끝나도 유지되는 장기 기억
skills/
스킬 폴더 — 3주차에 만든 SKILL.md 구조와 같은 계열이며, 헤르메스는 스스로 스킬을 만들어 여기 저장하기도 합니다
sessions/ · logs/
대화 기록과 동작 로그 — 에이전트가 무슨 일을 했는지 확인하는 감사 창구
3

OpenRouter 연동 — 두뇌 꽂기

헤르메스는 몸일 뿐, 두뇌(모델)는 밖에서 꽂아야 합니다. 2·3주차에 만들어 둔 OpenRouter API 키를 그대로 재사용합니다 — 새로 발급할 필요 없습니다.

1 .env에 키 넣기
📄 ~/.hermes/.env 
OPENROUTER_API_KEY=sk-or-v1-여기에-내-키
2 config.yaml에서 기본 모델 지정
📄 ~/.hermes/config.yaml 
model:
  provider: "openrouter"
  default: "anthropic/claude-sonnet-4.6"

OpenRouter를 통해 200개 이상의 모델을 같은 키로 바꿔 낄 수 있습니다. 한 번만 써 보려면 설정 없이 hermes chat --provider openrouter --model anthropic/claude-sonnet-4.6처럼 실행 시 지정할 수도 있습니다.

.env는 내 서버에만 3주차에는 키를 Vercel의 환경변수에 두었습니다. 헤르메스에서는 키가 내 컴퓨터의 ~/.hermes/.env에 놓입니다 — 편리하지만, OpenClaw 사고 원인 중 하나가 "평문으로 놓인 비밀"이었음을 기억하세요. 이 파일을 절대 git에 커밋하거나 메신저로 보내지 말고, 에이전트의 작업 폴더 안에 복사해 두지도 마세요(울타리 안의 비밀은 보호 대상이 아니라 작업 대상이 됩니다).
4

텔레그램 게이트웨이 — 페어링으로 연결

이제 입을 답니다. 텔레그램 봇을 만들어 헤르메스에 연결하면, 폰에서 말 거는 것만으로 내 서버의 에이전트가 움직입니다.

1 BotFather로 봇 만들기

텔레그램에서 @BotFather를 검색해 대화 시작 → /newbot → 봇 이름과 아이디(…bot으로 끝나야 함) 지정 → 발급된 봇 토큰을 복사해 둡니다. 이 토큰도 비밀입니다 — 키와 같은 등급으로 다루세요.

2 게이트웨이 설정
⌨️ 터미널 
hermes gateway setup

목록에서 Telegram을 선택하고, 1단계의 봇 토큰을 붙여넣습니다.

3 페어링 — 사용자 승인

텔레그램에서 내 봇에게 첫 메시지를 보내면 페어링 코드가 표시됩니다. 터미널에서 그 코드를 승인해야 대화가 시작됩니다:

⌨️ 터미널 
hermes pairing approve telegram 페어링코드
4 게이트웨이 시작
⌨️ 터미널 
hermes gateway start
①의 원칙, 두 번째 실물 — 페어링 코드가 곧 human-in-the-loop 왜 봇에게 바로 말을 걸 수 없게 해 놓았을까요? 봇 아이디는 사실상 공개 정보라, 승인 절차가 없다면 아무나 내 컴퓨터의 에이전트에게 명령을 보낼 수 있기 때문입니다. 페어링 코드는 "이 사람의 명령만 받는다"를 사람이 직접 승인하는 장치 — ①에서 배운 화이트리스트 + HITL이 실물로 구현된 모습입니다.
5

첫 대화와 안전 점검

폰을 들고 봇에게 말을 걸어 보세요 — "안녕, 너는 지금 어디서 실행되고 있어?" 응답이 오면, 여러분의 첫 자가 호스팅 에이전트가 깨어난 것입니다.

hermes status
에이전트·게이트웨이 동작 상태 확인
hermes doctor
환경 문제 진단 — 뭔가 안 될 때 첫 번째로 실행
hermes version
설치된 버전 확인

운영 전 안전 점검 — ①의 체크리스트를 이 자리에

1

terminal backend는 docker로. config.yaml에서 에이전트의 셸 실행을 Docker 컨테이너로 두면, 명령이 내 컴퓨터 본체가 아니라 일회용 컨테이너 안에서 돕니다. ⑤에서 배운 "모델이 속아도 OS가 막는" 구조입니다. 로컬 설치에서는 이 설정을 직접 챙겨야 합니다. Docker가 없거나 설정이 낯설면 Claude Code에 맡기면 됩니다.

2

페어링은 내 계정 하나만. 가족·친구 계정을 무심코 승인하지 않기. 승인 목록이 곧 화이트리스트입니다.

3

비밀은 .env에만, 작업 폴더 밖에. 에이전트가 읽고 다니는 폴더에 키·토큰 사본을 두지 않기.

4

logs/를 가끔 열어 본다. 자율은 무감독이 아닙니다 — 에이전트가 무슨 일을 했는지 확인하는 습관이 마지막 안전장치입니다.

6

마무리

  • 헤르메스 = 자가 호스팅 · 상시 상주 · 메신저로 부르는 오픈소스(MIT) 에이전트
  • 설치는 내 컴퓨터에 로컬로. 컴퓨터가 켜져 있는 동안 동작하고, 필요해지면 호스팅으로 옮길 수 있다
  • 두뇌는 OpenRouter로 — 2·3주차의 키 재사용, 키는 .env에만
  • 텔레그램 연결의 관문은 페어링 코드 — HITL·화이트리스트의 실물
  • terminal backend는 docker — 템플릿에 기본 적용된 "속아도 막히는" 구조를 깨지 않기
다음 강의 ⑦ — 나의 투자 위원회이 에이전트 위에 관점이 다른 봇 셋을 올립니다. 추세·리밸런싱·검증 담당이 포트폴리오를 놓고 토론하고, 주 1회 루틴으로 돌립니다. 결정은 나.
포트폴리오를 물려주기②~③에서 만든 시트와 서비스 계정 키를 이 서버가 읽게 해 두면, ⑦의 위원회가 내 실제 배분을 검토할 수 있습니다. 폴더째 공유해 둔 이유가 여기서 쓰입니다.
