WEEK 4 · STEP 5 — 에르메스 에이전트 ①

에르메스 에이전트 ① —
설치, 그리고 텔레그램·OpenRouter 연동

이론(①)과 연결(②③④)을 지나, 드디어 자율 에이전트를 직접 설치합니다. 에르메스(Hermes Agent)는 서버에 상주하며 텔레그램으로 말을 걸 수 있는 오픈소스 에이전트입니다. 설치는 Hostinger 호스팅의 원클릭 템플릿을 씁니다 — 24시간 켜져 있는 내 서버가 생기고, 도메인까지 붙이면 훌륭한 개인 서버가 됩니다. 이 자료에서 서버 만들기 → 두뇌(OpenRouter) 연결 → 텔레그램 연결 → 첫 대화까지 갑니다. ①에서 배운 안전 원칙이 실물로 등장하는 지점들을 놓치지 마세요.

1

에르메스란 — Claude와 뭐가 다른가

에르메스(Hermes Agent)는 Nous Research가 공개한 오픈소스(MIT 라이선스) 자율 AI 에이전트입니다. 지금까지 쓰던 Claude와의 차이는 기능이 아니라 존재 방식에 있습니다.

Claude (지금까지)에르메스 (오늘부터)
어디서 사나Anthropic의 서버 (나는 접속)내 컴퓨터/서버 (자가 호스팅)
언제 사나내가 대화창을 열 때상시 상주(persistent) — 세션이 끝나도 기억 유지
어떻게 부르나앱·웹·터미널메신저 게이트웨이 21개+ — 텔레그램·디스코드·슬랙 등
두뇌(모델)Claude 고정자유 — OpenRouter(200+ 모델)·OpenAI·자체 엔드포인트
확장스킬·MCP·커넥터스킬 자가 생성 + MCP + cron 루틴(⑥)

요약하면: 몸(실행 환경)은 내 것, 두뇌(모델)는 골라 꽂고, 입(대화 통로)은 메신저. 이 조합이 "내가 자는 동안 일하는 AI"를 가능하게 합니다. ①에서 배웠듯 바로 이 조합(사적 데이터 + 외부 콘텐츠 + 외부 통신)이 치명적 3요소이기도 합니다. 설치 과정 내내 안전장치를 함께 챙기는 이유입니다.

왜 에르메스인가 — 실행 환경의 자유도

굳이 서버까지 만들어 설치하는 이유는 하나입니다. 에이전트의 실행 환경을 내가 원하는 대로 설정할 수 있는 자유도입니다. 지금까지의 Claude는 Anthropic이 정해 둔 환경 안에서 쓰는 완성품입니다. 편하지만 정해진 틀 밖으로는 나갈 수 없습니다. 에르메스에서는 그 틀을 내가 정합니다:

  • 두뇌 : 작업마다 모델을 골라 꽂습니다. 비싼 추론 모델과 값싼 모델을 용도별로 나눠 쓸 수 있습니다
  • 도구와 기억 : 어떤 스킬과 MCP를 쥐여줄지, 무엇을 기억하게 할지를 내가 구성합니다
  • 시간 : 내가 부를 때만 도는 것이 아니라, 루틴(cron)으로 정해진 시각에 스스로 돌게 합니다
  • 통로 : 내가 매일 쓰는 메신저(텔레그램 등)를 대화 창구로 삼습니다
  • 역할 : 에이전트를 여럿 두고 역할과 성격을 다르게 설정합니다. 관점이 다른 봇들이 토론하는 투자 위원회가 이 자유도로 만들어집니다

자유도의 값은 책임입니다. 환경을 내가 정하는 만큼, 안전장치도 내가 챙깁니다(①의 원칙이 이 강의 곳곳에서 실물로 나오는 이유입니다).

2

설치 — Hostinger VPS에 원클릭으로

에이전트는 24시간 상주해야 의미가 있는데, 내 PC는 덮개를 닫으면 꺼집니다. 그래서 호스팅 서비스(Hostinger)의 VPS(가상 개인 서버)에 올립니다 — 원클릭 템플릿이 있어 설치 난이도가 크게 낮고, 도메인까지 연결하면 훌륭한 개인 서버가 됩니다.

1 VPS 플랜 + 에르메스 템플릿 선택

hostinger.com에서 VPS 플랜(KVM 2 권장, 월 몇 달러대 — 요금제는 결제 화면에서 확인)을 고르고, 설정 단계에서 템플릿으로 Hermes Agent를 선택합니다. 결제하면 시스템이 알아서 전부 설치합니다. 이 과정에서 웹 터미널 접속용 사용자명·비밀번호를 만들게 됩니다 — 길게, 문장형으로.

2 Docker Manager에서 열기

설치가 끝나면 관리 화면(hPanel)의 Docker Manager에 Hermes Agent가 프로젝트로 나타납니다. Open을 눌러 방금 만든 계정으로 로그인하면 — 브라우저 안에서 에르메스의 웹 터미널이 열립니다. 이후 이 자료의 모든 hermes ... 명령은 여기서 실행합니다. 이상하면 hermes doctor가 진단해 줍니다.

3 (선택) 도메인 연결 — 개인 서버 완성

hPanel → Domains → DNS/Nameservers에서 A 레코드를 추가합니다: hermes.내도메인.com → 내 VPS의 IP 주소. 1주차에 배운 도메인 연결과 같은 원리입니다 — 이제 IP 숫자가 아니라 내 도메인이 붙은 24시간 개인 서버가 생겼습니다.

왜 이 방식인가 — 난이도는 내려가고, 안전장치는 기본으로 ① 내 PC를 켜 둘 필요 없이 24시간 상주 ② API 키·대화 기록·데이터가 내 서버에만 남음 ③ 템플릿이 에르메스를 Docker 컨테이너로 돌리므로, ①강에서 배운 컨테이너 고립이 처음부터 적용된 상태로 시작합니다. 로컬 설치의 WSL2 준비·의존성 설치가 통째로 사라지는 것은 덤입니다.
내 PC에 직접 설치하고 싶다면 (대안) — Linux·macOS·WSL2에서 공식 스크립트 한 줄로도 됩니다: curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash 후 source ~/.bashrc. 단, curl … | bash는 인터넷의 코드를 그대로 내 컴퓨터에서 실행하는 명령입니다(①의 위험 구조와 같은 모양) — 주소가 공식 저장소(NousResearch/hermes-agent)인지 반드시 확인하고 실행하세요.

설치 후 서버에 생기는 것 — ~/.hermes/ 홈 폴더

config.yaml
에이전트 설정 — 모델, 게이트웨이, terminal backend 등
.env
API 키 보관소. 3주차 공식("비밀은 환경변수로")의 에르메스 버전 — §3에서 채웁니다
SOUL.md
에이전트의 성격·말투를 정하는 파일 — 마크다운으로 자유롭게 수정
memories/
세션이 끝나도 유지되는 장기 기억
skills/
스킬 폴더 — 3주차에 만든 SKILL.md 구조와 같은 계열이며, 에르메스는 스스로 스킬을 만들어 여기 저장하기도 합니다
sessions/ · logs/
대화 기록과 동작 로그 — 에이전트가 무슨 일을 했는지 확인하는 감사 창구
3

OpenRouter 연동 — 두뇌 꽂기

에르메스는 몸일 뿐, 두뇌(모델)는 밖에서 꽂아야 합니다. 2·3주차에 만들어 둔 OpenRouter API 키를 그대로 재사용합니다 — 새로 발급할 필요 없습니다.

1 .env에 키 넣기
📄 ~/.hermes/.env 
OPENROUTER_API_KEY=sk-or-v1-여기에-내-키
2 config.yaml에서 기본 모델 지정
📄 ~/.hermes/config.yaml 
model:
  provider: "openrouter"
  default: "anthropic/claude-sonnet-4.6"

OpenRouter를 통해 200개 이상의 모델을 같은 키로 바꿔 낄 수 있습니다. 한 번만 써 보려면 설정 없이 hermes chat --provider openrouter --model anthropic/claude-sonnet-4.6처럼 실행 시 지정할 수도 있습니다.

.env는 내 서버에만 3주차에는 키를 Vercel의 환경변수에 두었습니다. 에르메스는 자가 호스팅이므로 키가 내 서버(VPS)의 .env에 놓입니다 — 편리하지만, OpenClaw 사고 원인 중 하나가 "평문으로 놓인 비밀"이었음을 기억하세요. 이 파일을 절대 git에 커밋하거나 메신저로 보내지 말고, 에이전트의 작업 폴더 안에 복사해 두지도 마세요(울타리 안의 비밀은 보호 대상이 아니라 작업 대상이 됩니다).
4

텔레그램 게이트웨이 — 페어링으로 연결

이제 입을 답니다. 텔레그램 봇을 만들어 에르메스에 연결하면, 폰에서 말 거는 것만으로 내 서버의 에이전트가 움직입니다.

1 BotFather로 봇 만들기

텔레그램에서 @BotFather를 검색해 대화 시작 → /newbot → 봇 이름과 아이디(…bot으로 끝나야 함) 지정 → 발급된 봇 토큰을 복사해 둡니다. 이 토큰도 비밀입니다 — 키와 같은 등급으로 다루세요.

2 게이트웨이 설정
⌨️ 터미널 
hermes gateway setup

목록에서 Telegram을 선택하고, 1단계의 봇 토큰을 붙여넣습니다.

3 페어링 — 사용자 승인

텔레그램에서 내 봇에게 첫 메시지를 보내면 페어링 코드가 표시됩니다. 터미널에서 그 코드를 승인해야 대화가 시작됩니다:

⌨️ 터미널 
hermes pairing approve telegram 페어링코드
4 게이트웨이 시작
⌨️ 터미널 
hermes gateway start
①의 원칙, 두 번째 실물 — 페어링 코드가 곧 human-in-the-loop 왜 봇에게 바로 말을 걸 수 없게 해 놓았을까요? 봇 아이디는 사실상 공개 정보라, 승인 절차가 없다면 아무나 내 컴퓨터의 에이전트에게 명령을 보낼 수 있기 때문입니다. 페어링 코드는 "이 사람의 명령만 받는다"를 사람이 직접 승인하는 장치 — ①에서 배운 화이트리스트 + HITL이 실물로 구현된 모습입니다.
5

첫 대화와 안전 점검

폰을 들고 봇에게 말을 걸어 보세요 — "안녕, 너는 지금 어디서 실행되고 있어?" 응답이 오면, 여러분의 첫 자가 호스팅 에이전트가 깨어난 것입니다.

hermes status
에이전트·게이트웨이 동작 상태 확인
hermes doctor
환경 문제 진단 — 뭔가 안 될 때 첫 번째로 실행
hermes version
설치된 버전 확인

운영 전 안전 점검 — ①의 체크리스트를 이 자리에

1

terminal backend는 docker로. config.yaml에서 에이전트의 셸 실행을 Docker 컨테이너로 두면, 명령이 서버 본체가 아니라 일회용 컨테이너 안에서 돕니다 — ①에서 배운 "모델이 속아도 OS가 막는" 구조입니다. Hostinger 템플릿은 처음부터 Docker 기반이라 이 원칙이 기본 적용되어 있습니다 — 설정을 바꿀 때 이 구조를 깨지 않는 것이 핵심입니다.

2

페어링은 내 계정 하나만. 가족·친구 계정을 무심코 승인하지 않기. 승인 목록이 곧 화이트리스트입니다.

3

비밀은 .env에만, 작업 폴더 밖에. 에이전트가 읽고 다니는 폴더에 키·토큰 사본을 두지 않기.

4

logs/를 가끔 열어 본다. 자율은 무감독이 아닙니다 — 에이전트가 무슨 일을 했는지 확인하는 습관이 마지막 안전장치입니다.

6

마무리

  • 에르메스 = 자가 호스팅 · 상시 상주 · 메신저로 부르는 오픈소스(MIT) 에이전트
  • 설치는 Hostinger VPS 원클릭 템플릿 — 24시간 상주 + Docker 고립 기본, 도메인을 붙이면 개인 서버
  • 두뇌는 OpenRouter로 — 2·3주차의 키 재사용, 키는 .env에만
  • 텔레그램 연결의 관문은 페어링 코드 — HITL·화이트리스트의 실물
  • terminal backend는 docker — 템플릿에 기본 적용된 "속아도 막히는" 구조를 깨지 않기
