웹앱 만들기

지난 과제에서는 정적인 자기소개 페이지를 만들었습니다. 이번에는 HTML 파일 안에 <script>로 실제 프로그램(계산·그래프·게임)을 넣어, 브라우저 안에서 바로 실행되는 앱을 만들어봅니다.

시작하기 전에

자바스크립트란? — HTML 안에 들어있는 진짜 프로그램

HTML 파일 하나는 사실 세 가지 언어로 이루어져 있습니다.

HTML · CSS · JavaScript, 세 가지 역할

HTML은 뼈대(무엇이 있는지 — 제목, 버튼, 입력창 같은 요소들), CSS는 겉모습(어떻게 보이는지 — 색상, 크기, 배치), JavaScript는 동작(무엇을 계산하고, 무엇이 움직이는지)을 담당합니다. 여기에 <script>...</script> 태그로 JavaScript 코드를 끼워 넣으면, 그 코드가 서버 없이 내 브라우저 안에서 그대로 실행됩니다. 세 가지 모두 이 파일 하나에 들어있고, 별도의 서버 없이 브라우저가 전부 처리합니다. (2주차에서는 반대로 "왜 서버가 필요한 경우도 있는지"를 다룹니다.)

📄 sample.html — 세 언어가 파일 하나 안에 이렇게 들어있습니다
<!doctype html>
<html>
<head>
  <style>
    button { background: skyblue; border-radius: 8px; }
  </style>
</head>
<body>
  <button id="hi">눌러보세요</button>
  <script>
    document.getElementById('hi').onclick = () => alert('안녕!');
  </script>
</body>
</html>
HTML — 뼈대: 버튼이 하나 있다 CSS — 겉모습: 하늘색 배경, 둥근 모서리 JavaScript — 동작: 누르면 알림창이 뜬다

말로만 들으면 감이 안 오니, 아주 간단한 계산기로 직접 확인해봅시다. 숫자를 바꾸면 결과가 바로 바뀌는데, 이걸 만드는 JavaScript 코드는 몇 줄뿐입니다.

Part 3

단순 계산으로는 부족하다 — S&P 500 몬테카를로 시뮬레이션

위 그래프는 매년 정확히 같은 수익률이 반복된다고 가정합니다. 하지만 실제 주식 시장은 어떤 해는 +30%, 어떤 해는 -20%처럼 들쭉날쭉합니다. 몬테카를로 시뮬레이션은 "정답 하나"를 계산하는 대신, 무작위 상황을 수백 번 반복해서 가능한 결과들의 분포를 보여주는 방법입니다.

여기서는 실제 S&P 500의 1928~2024년(97개년) 연간 수익률 데이터를 이 파일 안에 그대로 담아두고, 그중에서 매년 무작위로 하나씩 뽑아(복원추출) 시뮬레이션합니다.

현재 조건: Part 2에서 설정한 연간 1,800만원 · 25년을 그대로 사용합니다.

몬테카를로 시뮬레이션이란? "미래 수익률은 매년 이럴 것이다"라고 하나로 단정하는 대신, 과거 데이터에서 있었던 실제 연도별 수익률을 무작위로 수백 번 뽑아 대입해보고, 그 결과들이 넓게 흩어져 있는 범위(분포)를 관찰하는 방법입니다. "다시 뽑기"를 누를 때마다 뽑히는 순서가 달라지므로 결과도 매번 조금씩 바뀝니다.
참고 이 시뮬레이션은 교육용 예시이며 투자 조언이 아닙니다. 과거 수익률(1928~2024년 S&P 500)이 미래 수익을 보장하지 않습니다.

Part 4

HTML로 할 수 있는 것들

오늘 만든 게임·플래너·시뮬레이션은 시작일 뿐입니다. 사실 보고서, 발표자료(PPT), 심지어 논문까지도 워드나 파워포인트 대신 HTML 한 파일로 만드는 사례가 늘고 있습니다. Anthropic의 아티클 "The Unreasonable Effectiveness of HTML"에서 소개한 대표적인 활용 분야는 아래와 같습니다.

기획서 · 계획 · 탐색

서로 다른 시안 여러 개를 그리드로 나란히 비교하거나, 프로젝트 진행 계획을 단계별로 정리한 문서

문서 비교 · 설명

계약서 같은 문서의 수정 전/후를 색상과 이유 설명으로 한눈에 비교할 수 있는 문서

리포트 · 리서치 · 학습 자료

여러 자료를 종합해 다이어그램·주석과 함께 정리한 설명 페이지

커스텀 편집 도구

한 걸음 더 — "우리만을 위한 사이트" 만들기

앞의 사례들이 문서를 대신하는 이야기였다면, 여기서 한 걸음 더 나갈 수 있습니다. 바로 특정한 사람·특정한 상황만을 위한 맞춤 웹사이트를 만들어, 그 사이트 자체를 정보를 주고받는 창구로 쓰는 것입니다.

카톡 대화, 이메일 첨부파일, 엑셀, 캡처 이미지에 흩어져 있던 내용을 한 페이지에 모아 링크 하나로 공유하면, 관련된 사람 모두가 같은 화면을 보면서 이야기하게 됩니다. "그 파일 어디 있죠?"가 사라지고, 대화가 항상 최신 정보 위에서 이루어집니다.

수업 발표도 마찬가지입니다. PPT를 만드는 대신 발표용 웹사이트를 만들어 링크를 띄워놓고 발표하면, 발표가 끝난 뒤에도 그 링크가 그대로 남아 팀원과 교수님이 언제든 다시 열어볼 수 있는 자료가 됩니다.

이런 것들도 똑같은 방식으로 만들 수 있습니다

  • 수업 발표 자료 — PPT 대신 발표용 사이트. 발표 후에도 링크가 남아 그대로 제출 자료가 됩니다.
  • 연구 프로젝트 현황판 — 실험 진행률, 데이터 정리, 참고문헌, 미팅 기록을 공동연구자와 한 화면에서 공유
  • 웨딩·행사 안내 페이지 — 일정·장소·드레스코드·오시는 길·참석 여부를 하객에게 링크 하나로
  • 병원·요양 간병 기록 — 투약 시간, 검사 일정, 특이사항을 가족들이 함께 확인하고 기록
  • 동아리·스터디 운영 페이지 — 모임 일정, 발표 순번, 자료 아카이브, 참석 체크
  • 제품 사용 설명 페이지 — 고객마다 다른 설정값·계약 조건을 반영한 맞춤 안내서
핵심은 "범용"이 아니라 "맞춤"입니다 시중의 협업 도구는 모든 사람에게 맞추느라 정작 내 상황엔 안 맞는 항목이 가득합니다. 반대로 AI에게 부탁해 만드는 사이트는 딱 이 사건, 딱 이 회원, 딱 우리 가족에게만 맞춰져 있어서 군더더기가 없습니다. 만드는 데 몇 분이면 되니, 필요 없어지면 그냥 버려도 아깝지 않습니다.
