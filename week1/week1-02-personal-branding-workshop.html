나만의 개인 브랜딩 사이트를 만들고
인터넷에 공개하기

이 페이지를 옆에 띄워두고 Cowork(Claude)를 함께 열어둔 채 순서대로 따라가세요. 브랜딩 전략을 정리하고, AI에게 요청해 사이트를 만들고, GitHub Pages로 실제 인터넷 주소에 배포하는 것까지 한 번에 끝냅니다.

시작하기 전에

이 실습에서 무엇을 만드나요?

Cowork(Claude)에게 요청해서 나만의 개인 소개 웹사이트(index.html)를 만들고, GitHub Pages를 통해 https://[내아이디].github.io 라는 실제 인터넷 주소로 배포합니다.

코드를 직접 쓰는 게 목표가 아닙니다. 무엇을 원하는지 정확히 정리해서 AI에게 요청하는 법을 익히는 것이 핵심입니다.

왜 개인 브랜딩 사이트?

이력서보다 유연하고, SNS보다 전문적입니다. 링크 하나로 나를 소개하는 가장 쉬운 방법입니다.

왜 GitHub Pages?

완전 무료로, 평생 유지되는 공개 URL을 받습니다.

오늘의 목표

브랜딩 설계 → 프롬프트 작성 → 사이트 생성 → GitHub 배포까지, 하나의 흐름으로 완주합니다.

Part 1

브랜딩 설계 — 프롬프트 쓰기 전에 4가지만 정리하기

좋은 프롬프트는 좋은 기획에서 나옵니다. 아래 4가지를 먼저 정하면, 프롬프트가 훨씬 명확해지고 결과물도 훨씬 좋아집니다.

학술적이지 않아도 됩니다

강사 예시 사이트는 학술적인 톤을 택했을 뿐입니다. 아래 3가지 예시처럼 완전히 다른 스타일도 얼마든지 좋은 개인 브랜딩 사이트가 됩니다. 카드를 클릭하면 크게 볼 수 있습니다.

예시 1 · 레트로 아케이드형

8비트 게임 캐릭터 스탯 창처럼 꾸민 스타일. 능력치 바(AI 활용력·코딩 경험치 등), 클리어한 퀘스트 로그, 픽셀 아바타로 "나"를 게임 캐릭터처럼 소개합니다. 개성과 유머를 드러내고 싶을 때 잘 어울립니다.

Part 2

index.html 만들기

Part 1에서 완성한 프롬프트를 그대로 Cowork(Claude)에게 붙여넣으세요. 잠시 후 완성된 웹사이트 코드가 도착합니다.

1

Cowork(Claude) 열기

평소 쓰던 Claude 대화창을 엽니다. 새 대화를 시작해도 좋습니다.

2

프롬프트 붙여넣고 전송

Part 1에서 복사한 프롬프트를 그대로 붙여넣고 전송합니다. 이름, 소속, 관심사·프로젝트, 연락처 같은 실제 정보는 프롬프트 뒤에 이어서 적어주면 더 좋습니다.

3

결과 확인하고 다듬기

Claude 답변에 표시된 파일(index.html)을 클릭하면, 오른쪽에 미리보기 창이 뜨면서 완성된 사이트를 바로 볼 수 있습니다. 따로 다운로드하거나 브라우저를 열 필요가 없습니다.

마음에 안 드는 부분은 자연스러운 말로 고쳐 달라고 요청하면 됩니다 — 몇 번이든 다시 요청할 수 있습니다. 자주 쓰는 수정 요청 예시:

전체 색상을 차분한 네이비 + 화이트 톤으로 바꿔줘.
다크모드 버튼을 오른쪽 위에 추가해줘.
"주요 프로젝트" 섹션을 카드 3개로 추가하고, 각 카드에 제목·한 줄 설명·링크를 넣어줘.

Part 3

다운로드 받기

완성된 사이트 파일을 내 컴퓨터에 저장합니다. 나중에 GitHub에 올릴 때 이 파일이 필요합니다.

1

파일로 받기

Cowork가 만든 결과물을 파일로 다운로드합니다. 채팅에 파일이 첨부돼 있다면 그대로 다운로드하세요.

2

이름은 반드시 index.html

파일 이름을 index.html로 정확히 저장합니다(대소문자·확장자 그대로).

파일명 주의 GitHub Pages는 index.html이라는 이름의 파일을 홈페이지로 인식합니다. index (1).html처럼 이름이 조금이라도 다르면 사이트가 뜨지 않습니다.

Part 4

GitHub 계정 만들기

이제 이 파일을 인터넷에 올릴 공간이 필요합니다. GitHub은 코드·파일을 인터넷에 보관하고 공유하는 서비스입니다.

먼저 알아두면 좋은 용어 4가지

실제 작업은 대부분 클릭 몇 번이면 충분합니다. 아래 뜻만 알아두세요.

GitHub (깃허브)
파일을 인터넷에 보관하고 공유하는 서비스. "파일용 클라우드 저장소"라고 생각하면 됩니다.
Repository (저장소·레포)
프로젝트 하나가 들어가는 폴더. 우리 사이트 파일(index.html)이 담길 공간입니다.
Commit (커밋)
변경 내용을 "이 시점의 저장본"으로 기록하는 것. 게임의 세이브 포인트와 비슷합니다.
Push / Upload (업로드)
내 파일을 GitHub 저장소로 올려보내는 것. 이 작업이 끝나야 인터넷에 반영됩니다.
1

GitHub 가입하기

github.com/signup에 접속해 이메일로 가입하고, 무료(Free) 플랜을 선택하세요.

2

아이디(Username) 정하기

이 아이디가 공개 URL에 그대로 들어갑니다. 예) 아이디가 dochon-lee라면 → https://dochon-lee.github.io. 영문·숫자·하이픈만 사용해 신중히 고르세요.

3

이메일 인증

가입 후 받은 인증 메일의 링크를 눌러 계정을 활성화합니다.

Part 5

저장소(Repository) 만들기

GitHub 우측 상단의 + → New repository를 클릭하고 아래처럼 설정합니다.

1

Repository name

이름을 [내아이디].github.io로 정확히 짓습니다. 예) 아이디가 dochon-lee라면 저장소 이름은 dochon-lee.github.io. 이렇게 지으면 별도 설정 없이 https://dochon-lee.github.io 주소가 바로 내 사이트가 됩니다.

2

공개 범위: Public

Public(공개)으로 만들어야 GitHub Pages 무료 배포가 가능합니다.

3

Add a README는 Off

체크하지 않고 완전히 빈 저장소로 만듭니다. 그래야 다음 단계에서 index.html만 깔끔하게 올릴 수 있습니다.

이름을 정확히 지어야 하는 이유 저장소 이름이 [내아이디].github.io가 아니면, 사이트 주소가 https://[내아이디].github.io/저장소이름처럼 길어집니다. 개인 대표 사이트라면 이 방식이 가장 깔끔합니다.

Part 6

index.html 업로드하기

이제 다운로드해둔 파일을 방금 만든 저장소에 올립니다.

1

Add file → Upload files

방금 만든 저장소 화면에서 Add file → Upload files를 클릭합니다.

2

드래그해서 업로드

Part 3에서 저장한 index.html 파일을 화면 위로 드래그해서 올립니다.

3

Commit changes

페이지 하단의 Commit changes 버튼을 눌러 저장을 마칩니다.

Part 7

GitHub Pages로 배포하기

마지막 단계입니다. 저장소에 올린 파일을 실제 웹사이트로 켜는 스위치를 누릅니다.

1

Settings → Pages

저장소 상단 메뉴에서 Settings → 왼쪽 메뉴의 Pages로 이동합니다.

2

Source를 main 브랜치로 지정

Branch 항목에서 main을 선택하고 Save를 누릅니다.

3

1~2분 후 URL 접속

화면에 나타나는 https://[내아이디].github.io 주소로 접속해 확인합니다.

바로 안 떠도 정상입니다 배포 후 URL이 실제로 반영되기까지 1~2분 정도 걸립니다. 안 뜬다면 잠시 기다렸다가 새로고침 해보세요.

Finish

축하합니다 — 내 손으로 만든 사이트가 인터넷에 있습니다

브랜딩을 설계하고, AI에게 요청해 사이트를 만들고, GitHub Pages로 배포까지 마쳤습니다. 이제 https://[내아이디].github.io 주소를 명함·이메일 서명·SNS 프로필에 붙여 보세요.

내용 계속 키우기

프로젝트, 글, 사진을 Cowork에게 추가해 달라고 요청하고 같은 이름으로 다시 업로드하면 사이트가 업데이트됩니다.

2주차 예고

다음 주에는 텍스트를 벡터로 바꾸는 임베딩을 배우고, 이를 활용한 웹앱을 만듭니다.

나만의 도메인 연결

원한다면 GitHub Pages의 Custom domain 설정으로 이름.com 같은 개인 도메인을 연결할 수 있습니다.

보너스

Claude Code로 GitHub 연동하기

지금까지는 채팅(Cowork)으로 파일을 받아, 매번 직접 다운로드해서 GitHub에 다시 업로드했습니다. 파일을 수정할 때마다 이 과정을 반복해야 합니다.

Claude Code(내 컴퓨터에서 실행하는 Claude)를 쓰면 다릅니다. 작업 폴더와 GitHub 저장소를 한 번 연결해 두면, 이후에는 파일을 고쳐 달라고 요청할 때마다 Claude가 수정 → 커밋 → 푸시까지 알아서 처리해서, 매번 다시 업로드할 필요가 없습니다.

1

Claude Code 실행하기

내 컴퓨터에 Claude Code를 설치한 뒤 실행합니다. (설치가 안 되어 있다면 Claude에게 "Claude Code 설치 방법 알려줘"라고 물어보세요.)

2

작업 폴더 만들고 연동하기

내 컴퓨터에 빈 폴더(예: my-site)를 하나 만들고, 그 폴더 안에서 Claude Code를 실행합니다. 이제 이 폴더가 Claude Code의 작업 공간이 됩니다.

3

index.html 저장 요청하기

Part 1에서 만든 프롬프트를 그대로 붙여넣되, 맨 앞에 "이 폴더에"를 붙여서 요청하면 Claude Code가 폴더 안에 바로 index.html을 저장합니다.

이 폴더에 나를 소개하는 홈페이지를 index.html 한 파일로 만들어줘.
4

GitHub 저장소 주소 알려주기

Part 5에서 만든 저장소 주소(https://github.com/[내아이디]/[내아이디].github.io.git)를 알려주면, Claude Code가 git 초기화·커밋·푸시까지 한 번에 처리합니다.

이 폴더를 [저장소 주소] 깃허브 저장소에 올려줘.
git 초기화하고, index.html을 커밋한 다음 푸시해줘.
커밋 메시지는 "내 홈페이지 첫 배포"로 해줘.
이후부터는 이렇게만 하면 됩니다 다음에 사이트를 고치고 싶으면 원하는 내용을 말한 뒤 "변경사항 커밋하고 푸시해줘"라고만 하세요. Claude Code가 알아서 GitHub에 반영하고, 몇 분 안에 공개 사이트에도 그대로 나타납니다. 더 이상 파일을 직접 다운로드하고 다시 업로드할 필요가 없습니다.
GitHub 로그인 안내가 나오면 Claude Code가 처음 푸시할 때 GitHub 인증을 요청할 수 있습니다. 화면 안내에 따라 한 번만 로그인하면, 이후에는 별도 로그인 없이 바로 처리됩니다.
