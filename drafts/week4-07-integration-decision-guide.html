WEEK 4 · STEP 7 — 총정리

무엇을 쓸지 어떻게 정하나 —
판단표 한 장, 그리고 4주의 마무리

부트캠프의 마지막 자료입니다. 3주차의 연동 다섯 갈래에 이번 주의 자율 에이전트·루틴 갈래를 더해 판단표를 완성하고, 사례 자가 점검과 도전 과제를 거쳐, 4주 전체의 여정을 접어 넣습니다. 앞으로 "이런 걸 만들고 싶은데"라는 생각이 들 때마다 이 표에서 시작하면 됩니다.

1

판단표 — 여섯 가지 길

질문 순서대로 내려가면 됩니다. "어디서 배웠나"가 복습 지도이기도 합니다.

질문답이 "예"라면쓰는 것어디서 배웠나
Q1. 나 혼자, 대화로 데이터를 분석·정리하고 싶은가?서비스를 만들 필요가 없음커넥터 (MCP)4주차 ②
Q2. 여럿이 쓰는 화면이 필요하고, 데이터가 공개 + 읽기 전용인가?백엔드 불필요정적 페이지 + 게시 CSV4주차 ③ §1
Q3. 비공개 데이터이거나 쓰기가 필요한가?비밀(키)을 숨길 서버 필요백엔드 (Vercel + 환경변수)3주차 배포 · 4주차 ③
Q4. 접속하는 사람을 가려야 하는가?Q3에 문을 추가+ 인증 (이메일 코드 등)3주차 인증
Q5. 상대 시스템에 MCP도 API도 없는가 (레거시)?어댑터를 직접 제작CLI 도구 + 에이전트4주차 ②
Q6. 시킬 때마다 한 번이 아니라, 스스로 반복되어야 하는가?실행 주체를 예약루틴 / 자율 에이전트4주차 ⑤⑥
전 구간을 관통한 한 문장 비밀은 서버에, 환경변수로. OpenRouter 키(3주차 배포), 서비스 계정 키(④), Gmail 앱 비밀번호(3주차 인증), 에르메스의 .env와 봇 토큰(⑤) — 무엇이 등장하든 자리는 하나였습니다. 이 문장 하나를 지키는 것이 비개발자가 지킬 수 있는 가장 중요한 보안 수칙입니다.
2

새 갈래 — "사람이 시킬 때마다 하나, 스스로 반복되나"

Q6은 이번 주에 새로 생긴 축입니다. 앞의 다섯 질문이 "무엇을 어떻게 연결하나"였다면, Q6은 "누가 실행 버튼을 누르나"를 묻습니다.

Q6에 "예"라고 답했다면 한 번 더 갈립니다 — ⑥의 결론 그대로입니다:

Claude 루틴으로 충분한 경우 (대부분)

  • 정해진 시각의 조사·요약·보고 작업
  • 결과를 내가 확인하는 형태면 충분
  • 설치·업데이트·보안을 맡기고 싶다
  • → Claude의 스케줄 루틴 + 스킬 + MCP 조합

자가 호스팅(에르메스)이 필요한 경우

  • 내 서버·내부망 환경에 24시간 상주해야 함
  • 팀의 메신저(텔레그램·슬랙)가 접점
  • 오픈 모델로 비용을 직접 통제
  • 데이터를 내 인프라 밖으로 못 내보냄
순서 요령 — Q6는 항상 마지막에 묻습니다. 먼저 Q1~Q5로 연동의 모양을 정하고, 그다음 "이걸 사람이 돌리나, 루틴이 돌리나"를 정하는 순서입니다. 예: "매일 아침 재고를 요약해 시트에 기록" = Q5(레거시 CLI) + Q3(시트 쓰기) + Q6(루틴)의 조합.
3

자가 점검 — 사례를 배치해 보기

아래 일곱 사례를 판단표에 넣어 보세요. 스스로 답한 뒤 펼쳐서 확인합니다.

1. 동아리 공지·행사 일정을 보여주는 페이지 (누구나 열람)

공개 + 읽기 → Q2: 정적 페이지 + 게시 CSV. 일정 시트만 게시하면 백엔드가 필요 없습니다.

2. 세미나 참가 신청 페이지 (이름·이메일 제출)

쓰기 발생 + 신청자 명단은 비공개 → Q3: 백엔드. ③의 append 패턴에서 열과 화면만 바꾸면 됩니다.

3. 회사 팀의 주간 실적 보드 (팀원만 열람·수정)

쓰기 + 사람을 가려야 함 → Q3+Q4: 백엔드 + 인증. ③의 팀 현황판에 3주차의 이메일 인증을 얹은 구성입니다.

4. 이번 달 내 지출 시트를 분석하고 절약 조언 받기

나 혼자 + 대화형 → Q1: 커넥터. 서비스를 만들 이유가 없습니다. 5분이면 끝나는 일에 배포를 하지 마세요.

5. 사내 구형 재고 시스템의 데이터를 매주 요약 보고

MCP도 API도 없는 레거시 → Q5: CLI 어댑터 — 그리고 "매주"이므로 +Q6: 루틴. 조회 CLI를 만들어 쥐여주고, 루틴이 매주 실행해 보고하게 합니다.

6. 내 블로그 방문자에게 보여줄 실시간 인기글 순위 (원본 통계 시트는 비공개)

함정 사례 — 화면은 공개지만 원본이 비공개 → Q2가 아니라 Q3: 백엔드. 읽기 전용이어도 비공개 데이터면 키가 필요합니다. "공개인가"는 화면이 아니라 데이터 원본에 묻는 질문입니다.

7. 팀 텔레그램 방에서 "어제 매출 알려줘"라고 물으면 답하는 봇 (사내 규정상 데이터 반출 금지)

메신저 접점 + 데이터 주권 → Q6의 자가 호스팅 갈래: 에르메스류 에이전트. ⑥의 네 가지 경우 중 두 개(메신저, 데이터 주권)에 해당하므로 관리형이 아닌 자가 호스팅이 정답입니다. 페어링·docker 격리(①⑤)는 필수.

4

자율 도전 과제

수료 후 도전할 것들입니다. 난이도 순이며, 하나만 해도 충분합니다. 결과는 수업 커뮤니티에 공유해 주세요.

난이도과제사용 자료
기본내 반복 업무 하나를 골라 절차를 SKILL.md로 저장하고, 관련 질문에 자동 발동되는지 확인3주차 ⑤
권장내 업무 루틴 하나를 자동화 — Claude 스케줄 루틴 또는 에르메스 cron으로 아침 브리핑·주간 보고를 예약⑤⑥
도전루틴 + 시트 연동 파이프라인 — 루틴이 매일 수집·요약한 결과를 시트에 append하고, 게시 CSV 대시보드로 보기③⑤⑥
심화에르메스의 terminal backend를 docker로 구성하고, 페어링·화이트리스트·로그 확인까지 ①의 안전 체크리스트를 전부 적용①⑤⑥
막혔을 때의 순서: ① 에러 메시지·로그를 통째로 복사해 AI에게 → ② 해당 자료의 "막혔을 때" 콜아웃 확인 → ③ 커뮤니티에 스크린샷과 함께 질문. "안 돼요"보다 "이 로그가 나와요"가 열 배 빨리 해결됩니다.
5

4주의 여정 — 수료를 축하합니다

4주 전, 터미널을 처음 여는 것부터 시작했습니다. 지금 여러분의 도구함에는:

  • 1주차 — 터미널·Git·GitHub Pages·HTML: 만들고 세상에 내놓는 기본기
  • 2주차 — 크롤링·수집·임베딩·판단 지도: 데이터를 모으고 구조를 보는 파이프라인 (판결문 347건이 지도가 되는 과정)
  • 3주차 — 검색엔진·RAG·Vercel 배포·인증: 데이터를 서비스로 바꾸고 보호하는 법
  • 4주차 — MCP·CLI·시트 연동·자율 에이전트: 그 전부를 연결하고, AI에게 맡기는 법

이 과정에서 판결문은 재료였을 뿐입니다. 여러분의 회사 문서, 고객 문의, 시장 데이터 — 무엇을 넣어도 수집 → 구조화 → 검색 → 서비스 → 자동화의 절차는 같습니다. 데이터가 바뀌어도 절차는 같다 — 이 문장이 4주의 요약이고, 여러분이 가져가는 진짜 자산입니다.

마지막 문장 1주차의 여러분은 "AI를 써 보는 사람"이었습니다. 지금 여러분은 URL이 있고, 파이프라인이 있고, 자는 동안 일하는 에이전트가 있는 사람입니다. 수료를 진심으로 축하합니다. 이제 여러분의 데이터로, 여러분의 절차를 돌리세요. 👋🎓
수료 후에 해 보기내 업무 루틴 하나를 에이전트/루틴으로 자동화하기 (§4의 권장 항목). 2주 안에 한 번 돌아가게 만드는 것을 목표로 삼아 보세요.
