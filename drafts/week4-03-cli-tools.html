WEEK 4 · STEP 3 — 만능 어댑터

CLI — MCP가 없는 시스템을
AI에 잇는 만능 어댑터

②의 연동 대상(구글 드라이브·시트)은 운이 좋은 경우였습니다 — 잘 만든 MCP 서버가 이미 있으니까요. 회사에 들어가면 다른 풍경을 만납니다: 10년 전 구축한 ERP, 부서 NAS의 엑셀 수천 개, 담당자가 퇴사한 구형 DB. 이런 시스템을 위해 MCP 서버를 개발하는 것은 정석이지만 개발자와 예산이 필요합니다. 오늘은 훨씬 가벼운 우회로 — 명령줄 도구(CLI)를 배웁니다.

1

발상의 전환 — 통로를 만드는 대신, 도구를 쥐여준다

CLI(Command-Line Interface)는 화면 없이 명령줄에서 텍스트로 부리는 프로그램입니다. Claude Code와 3주차 내내 함께 일한 그 터미널의 세계죠. 연결의 발상을 뒤집는 열쇠가 여기 있습니다.

지금까지 — 통로를 만든다

  • 시스템 쪽에 문(MCP 서버·API)을 만들어
  • AI가 그 문으로 들어가게 한다
  • 문이 없으면? → 연결 불가

발상 전환 — 도구를 쥐여준다

  • 그 시스템을 다룰 줄 아는 작은 프로그램(CLI)을 준비해
  • AI에게 "필요하면 이 도구를 실행해"라고 알려준다
  • AI가 스스로 도구를 골라 실행하고 결과를 읽는다

이것이 가능한 이유는 이미 경험했습니다 — Claude Code는 터미널 명령을 실행할 수 있습니다. 그리고 CLI의 세 성질이 AI와 정확히 맞물립니다:

CLI의 성질AI와의 궁합
입출력이 전부 텍스트텍스트는 AI가 가장 잘 읽고 쓰는 것 — 화면을 볼 필요가 없다
한 가지 일만 한다언제 쓸지 판단하기 쉽고, 잘못 써도 피해 범위가 좁다
조립이 된다A의 출력을 B의 입력으로 — 조립 설계는 AI가 스스로 한다
하나 더 — 도구가 스스로 설명서를 들고 다닙니다. 거의 모든 CLI는 --help를 붙이면 사용법을 출력합니다. 처음 보는 도구를 만나면 AI가 먼저 --help를 읽고 문법을 익힌 뒤 씁니다 — 사용자가 문법을 외울 필요가 없는 이유입니다.
2

이미 있는 도구 쥐여주기 — 사용 예시 네 가지

세상에는 수십 년간 다듬어진 명품 CLI가 이미 가득합니다. 설치만 되어 있으면 전부 AI의 도구함이 됩니다. 문법을 몰라도 됩니다 — 한국어로 시키면 AI가 알맞은 명령을 조립해 실행합니다.

🌩️
Google Cloud CLI — 구글의 공식 CLI 묶음구글이 자사 클라우드 전체를 CLI 제품군(suite)으로 제공합니다 — gcloud(자원 관리), gcloud storage(파일 저장소), bq(BigQuery 대용량 데이터 조회). 웹 콘솔에서 클릭으로 하던 일이 전부 명령줄로 됩니다.
🎬
ffmpeg — 영상·음성 변환영상 편집 프로그램 없이 변환·자르기·추출을 하는 사실상의 업계 표준.
📄
pandoc — 문서 변환마크다운↔워드↔HTML↔PDF 등 문서 형식 사이의 만능 번역기.
🖼️
ImageMagick — 이미지 일괄 처리수백 장의 이미지를 리사이즈·형식 변환·워터마크까지 명령 한 줄로 일괄 처리하는 고전 명가.

실제로 시켜 보면 — 프롬프트는 그냥 한국어입니다

💬 예시 1 · Google Cloud CLI — 클라우드로 데이터 백업 
이번 주에 만든 embeddings/ 폴더(JSON 347개)를 구글 클라우드
스토리지 버킷에 백업해줘. gcloud storage를 쓰고,
업로드가 끝나면 파일 개수가 로컬과 일치하는지 확인해줘.
💬 예시 2 · ffmpeg — 강의 녹화에서 음성 추출 
recordings/ 폴더의 강의 녹화 mp4들에서 음성만 mp3로 추출해줘.
파일명은 그대로 두고 확장자만 바꿔서 audio/ 폴더에 저장해줘.
💬 예시 3 · pandoc — 보고서 형식 변환 
report.md를 회사에 제출할 워드 문서(docx)로 변환해줘.
제목·표·각주가 깨지지 않는지 변환 후 확인해줘.
💬 예시 4 · ImageMagick — 사진 일괄 변환 
photos/ 폴더의 사진 300여 장을 전부 가로 1200px로 줄이고
webp 형식으로 변환해서 web/ 폴더에 저장해줘. 원본은 건드리지 마.

네 예시의 공통점을 보세요 — 사용자는 ffmpeg의 옵션도, ImageMagick 문법도 쓰지 않았습니다. "무엇을 원하는지"만 말하면, AI가 도구를 고르고(--help를 읽어서라도) 명령을 조립해 실행하고 결과를 해석합니다. 도구가 설치되어 있지 않으면 설치부터 제안합니다 — 이때 ①의 원칙대로 설치 승인은 읽고 누르세요.

직접 해보기 (2분) Claude Code에 이렇게 물어보세요: "지금 이 컴퓨터에 설치된 CLI 도구 중 내가 업무에 쓸 만한 것들을 찾아서 각각 뭘 하는 도구인지 설명해줘." — 내 도구함에 뭐가 있는지 AI가 목록을 만들어 줍니다.
3

없는 도구는 만든다 — 레거시 어댑터

사내 구형 시스템에는 gcloud 같은 기성 CLI가 없습니다. 하지만 우리에게는 CLI를 만들어 주는 AI가 있습니다 — 시스템은 한 줄도 고치지 않고, 그 시스템을 다룰 줄 아는 작은 도구를 옆에 만들어 꽂는 것입니다.

1
어댑터 제작 — 접속 방법을 알려주고 만들게 한다
💬 예시: 부서 공유폴더의 주간보고 엑셀 수백 개 
부서 공유폴더(N:\팀자료\주간보고)에 주간보고 엑셀이 몇 년치 쌓여 있어.
파일명 규칙은 "주간보고_YYYYMMDD_작성자.xlsx"이고 시트 구조는 다 똑같아
(진행 항목 / 이슈 / 다음 주 계획 표).
이 폴더의 데이터를 정리해 주는 CLI 도구(report.py)를 만들어줘:
- 기간·작성자로 해당 파일들을 골라, 세 표의 내용을 항목별로
  깔끔한 텍스트로 추출·출력 (요약하지 말고 원문 그대로)
- 특정 프로젝트명이 언급된 행만 골라내는 검색 기능
- 작성자별·주차별 이슈 건수를 세는 집계 기능
사용법은 --help에 담아줘.

구형 DB라면 접속 주소와 계정(읽기 전용 권장)을, 사내 웹 시스템이라면 화면 구조를 알려주면 됩니다. 접속 정보를 설명할 수 있으면 어댑터는 만들 수 있습니다.

역할 분담 — 도구는 "정리"까지, "요약·판단"은 AI가 어댑터에 요약 기능을 넣지 않은 것은 실수가 아닙니다. 요약·해석에는 LLM이 필요한데, 도구 안에서 LLM을 부르면 도구가 무겁고 비싸지고 결과도 매번 달라집니다. 그래서 어댑터는 결정적(deterministic) 작업만 맡습니다 — 찾기, 추출, 세기, 정리. 같은 입력이면 언제나 같은 출력이 나오는 일들이죠. 그 정리된 출력을 읽고 요약·판단하는 것은 도구를 쥔 AI(Claude Code)의 몫입니다. 이 분업이 §1에서 본 "한 가지 일만 한다"의 실전형입니다.
2
도구의 존재를 CLAUDE.md에 기록
💬 이어서 
방금 만든 report.py의 존재와 사용법을 CLAUDE.md에 추가해줘 —
"주간보고 관련 질문이 오면 이 도구를 사용할 것"이라고.

3주차 문서화에서 배운 그대로입니다 — CLAUDE.md는 다음 세션의 AI가 읽는 문서이므로, 여기 적어 두면 내일의 AI도 이 도구를 압니다.

3
이후로는 그냥 일상어로

"이번 달 A프로젝트 관련 주간보고 요약해줘"라고 물으면, AI가 report.py로 해당 데이터를 뽑아 온 뒤 그 출력을 읽고 요약해 답합니다 — 데이터 정리는 도구가, 요약은 AI가. 레거시 시스템은 한 줄도 바뀌지 않았는데, AI가 그 시스템을 쓰게 되었습니다.

어댑터에도 ①의 원칙 어댑터는 되도록 읽기 전용으로 시작하세요(조회만, 수정·삭제 없음). 쓰기 기능이 필요해지면 그때 별도 명령으로 추가하고, 실행 승인을 반드시 읽습니다. DB 계정도 읽기 전용 계정을 따로 받는 것이 안전합니다 — 도구의 권한이 곧 AI의 권한입니다.
4

MCP vs CLI — 판단 기준과 마무리

MCP (커넥터) — ②CLI (어댑터) — 오늘
언제표준 규격의 MCP 서버가 이미 있는 서비스 (드라이브·슬랙·노션…)MCP가 없는 시스템 — 레거시, 사내 전용, 파일 뭉치
준비물커넥터 켜기 + 권한 승인기성 CLI 설치, 또는 AI에게 어댑터 제작 요청
강점표준이라 어디서나 같은 방식, 관리되는 보안무엇이든 연결 가능, 시스템 무수정, 즉시 제작
주의권한 승인 화면을 읽을 것 (②)읽기 전용부터, 도구의 권한 = AI의 권한
이번 주의 표어 MCP는 표준 규격, CLI는 만능 어댑터. 규격이 있으면 MCP로 깔끔하게, 없으면 CLI를 쥐여줍니다. 그리고 도구 선택–실행–해석을 스스로 반복하는 이 구조가 바로 ①에서 정의한 에이전트입니다 — ⑤⑥의 에르메스는 MCP(표준 도구함)와 CLI(맞춤 도구)를 모두 쥐게 됩니다.
  • CLI = 텍스트로 부리는 프로그램 — 텍스트 입출력·단일 기능·조립성이 AI와 맞물린다
  • 이미 있는 도구(Google Cloud CLI·ffmpeg·pandoc·ImageMagick…)는 설치만 되면 AI의 도구함 — 문법은 AI가 --help로 익힌다
  • 어댑터는 결정적 작업(찾기·추출·세기)까지 — 요약·판단은 도구를 쥔 AI의 몫
  • 없는 도구는 만든다: 어댑터 제작 → CLAUDE.md 기록 → 일상어로 사용
  • 어댑터는 읽기 전용부터 — 도구의 권한이 곧 AI의 권한
다음 자료 ④ — 구글 시트 연동세 번째 길 — 내 웹앱이 구글 시트를 직접 읽고 쓰는 연동. "웹에 게시"의 백엔드 없는 읽기부터 서비스 계정, 팀 현황판까지 한 편에.
