데이터 분석 & 백엔드 아키텍처

웹에서 데이터를 모으고, 텍스트를 의미의 좌표(임베딩)로 바꾸고, 그 좌표로 지도와 검색엔진과 RAG 챗봇을 만듭니다. 하나의 판결문 코퍼스를 처음부터 끝까지 관통하는 수집 → 구조화 → 시각화 → 질의응답의 파이프라인이며, 그 과정에서 "왜 여기서부터는 백엔드가 필요한가"를 몸으로 배웁니다. 아래 자료를 순서대로 열어 따라가시면 됩니다.

📘 강의자료 9개 🧪 예제 데이터 직장 내 괴롭힘 판결문 347건 🎯 산출물 내 PC에서 도는 유사 판례 검색엔진 · RAG 챗봇
2주차 강의자료

하나의 데이터를 끝까지 따라가는 9개의 자료

①②③은 데이터를 모아 의미로 재고 지도로 그리는 과정, ④⑤⑥은 그 결과를 검색엔진으로 만들며 백엔드를 이해하는 과정, ⑦⑧⑨는 검색 위에 답변·자동화·다른 시각화를 얹는 과정입니다. 앞 자료의 산출물이 뒤 자료의 재료가 되므로 순서대로 보시는 것을 권합니다.

1수집 → 2임베딩 → 3지도 → 4도구 → 5검색 비교 → 6검색엔진 → 7RAG → 8스킬 → 9네트워크
PART 1

데이터를 모으고, 의미로 재고, 지도로 그린다

①–③ · 전 과정 Cowork
01

Cowork로 웹 스크래핑 실습

복사–붙여넣기 수백 번 대신 요청 문장 하나로 웹 데이터를 모읍니다. 정적/동적 사이트의 차이와 페이월·공정이용 같은 법적 경계, 그리고 수집 직후의 탐색적 분석(EDA)까지 실제 수집 기록으로 따라갑니다.

→ 02

임베딩 추출 파이프라인 개념 실습

텍스트를 "읽는" 대신 "재는" 방법 — 판결문 347건을 4,096차원 벡터로 바꿉니다. 임베딩이 무엇인지, OpenRouter로 모델을 어떻게 고르는지, API 키를 어떻게 안전하게 다루는지를 실제 실행 기록으로 배웁니다.

→ 03

판결문 347건의 지도 실습

클러스터링으로 다섯 개의 사건 유형을 찾고, 차원축소로 4,096차원을 한 장의 2D 지도로 만듭니다. 페이지 안의 지도는 실제 데이터이며, 직접 점을 눌러 탐색할 수 있습니다.

→
PART 2

검색엔진을 만들며 백엔드가 필요한 이유를 배운다

④–⑥ · 여기서 Claude Code로 갈아탑니다
04

Chat · Cowork · Claude Code 개념 설치

같은 Claude인데 무엇이 다른가 — 차이는 "AI의 손발이 어디에 놓여 있는가"입니다. 왜 서버 실습만은 Claude Code여야 하는지 정리하고, 다음 실습을 위해 Claude Code 설치까지 미리 끝냅니다.

→ 05

키워드 vs 임베딩 — 두 가지 검색 개념 체험

페이지 안의 검색창 두 개가 실제로 동작합니다. 키워드 검색이 동의어·표현 차이·의도 앞에서 무너지는 것을 직접 확인하고, 새 질의를 받으려면 왜 백엔드가 필요해지는지에 도달합니다.

→ 06

유사 판례 검색엔진 만들기 실습

KIPRIS 유사 특허 검색과 같은 산업 표준 아키텍처(색인 국면 + 검색 국면)를 이해하고, Claude Code에게 계획서부터 쓰게 하는 방식으로 내 PC에 검색 백엔드와 웹앱을 실제로 띄웁니다.

→
PART 3

검색 위에 답변을 얹고, 절차를 파일로 남긴다

⑦–⑨ · 연구·업무로의 확장
07

RAG와 Long Context 개념 실습

검색엔진이 "문서 목록"을 준다면 RAG는 "근거가 달린 답변"을 씁니다. 컨텍스트에 실제로 무엇이 담기는지 실물로 확인하고, 대안인 Long Context 방식과 둘을 섞은 하이브리드까지 비교해 상황에 맞게 고르는 기준을 세웁니다.

→ 08

나만의 스킬 만들기 실습

매번 다시 쓰던 긴 프롬프트를 SKILL.md 파일 한 장으로 저장하면, 관련 질문이 올 때마다 AI가 알아서 같은 절차로 움직입니다. 절차는 스킬에, 데이터는 프로젝트에 — 자리를 나누는 원칙까지 함께 배웁니다.

→ 09

논문 계보도 — 네트워크 분석 실습

같은 파이프라인을 논문 데이터에 적용합니다. "AI는 인간 노동을 대체하는가"를 둘러싼 문헌 23편의 인용 관계를 시간축 네트워크로 그리고, 후속 프롬프트로 읽기 계획과 열린 연구 질문까지 뽑아냅니다.

다음 주차

3주차 — 외부 데이터 연동하기

2주차에 만든 로컬 백엔드를 클라우드로 옮기고, 구글 드라이브·구글 폼 같은 외부 데이터 출처와 연동해 실시간으로 갱신되는 대시보드를 만듭니다. 데이터가 공개인지 비공개인지에 따라 백엔드가 필요한지 아닌지를 판단하는 기준을 다집니다.
