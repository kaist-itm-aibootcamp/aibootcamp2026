WEEK 2 · STEP 1 — 도구의 지형

같은 Claude, 세 개의 작업대 —
Chat · Cowork · Claude Code

1주차는 브라우저의 claude.ai에서 대화하고 아티팩트를 받는 것으로 충분했습니다. 2주차부터는 다릅니다 — 수백 건의 데이터를 내 PC 폴더에 파일로 쌓습니다. 그래서 작업대를 웹에서 로컬로 내립니다. 세 작업대의 차이를 정리하고, 이번 주(2주차) 전 과정에서 쓸 Claude 데스크톱 앱 · 크롬 확장, 그리고 3주차부터 본격적으로 쓸 Claude Code까지 한 번에 설치합니다.

1

세 개의 작업대 — 무엇이 다른가

셋 다 같은 Claude 모델과 대화하지만, AI의 손발이 어디에 놓여 있는지가 다릅니다. 손발의 위치가 할 수 있는 일을 결정합니다.

CLAUDE CHAT

브라우저 속 대화 상대 1주차에 쓴 claude.ai

  • 실행 위치: 없음 — 대화와 문서 생성 중심
  • 파일: 업로드한 것만 읽음
  • 산출물: 답변, 아티팩트(문서·웹앱 미리보기)
  • 강점: 질문·초안·아이디어 정리, 가장 낮은 진입장벽
  • 한계: 내 파일시스템·장시간 작업 접근 불가
COWORK

클라우드 작업실 + 내 폴더 데스크톱 앱에서 실행 · 이번 주(2주차)의 주력

  • 실행 위치: 클라우드 컨테이너 (자체 파일시스템·파이썬·인터넷)
  • 파일: PC 폴더 연동으로 내 자료를 읽고 씀
  • 산출물: 수집 데이터, 보고서, 파일 수백 개짜리 파이프라인
  • 강점: 웹 수집, 대량 문서 처리, 장시간 자율 작업
  • 한계: 내 PC에서 프로그램을 "실행"하지는 못함
CLAUDE CODE

내 컴퓨터의 터미널 3주차부터의 주력

  • 실행 위치: 내 PC — 터미널에서 직접 명령 실행
  • 파일: 현재 폴더의 파일을 직접 읽고·쓰고·실행
  • 산출물: 실행되는 프로그램 — 서버를 켤 수 있음
  • 강점: 로컬 백엔드, 개발 워크플로, 내 환경 제어
  • 한계: 터미널이라는 낯선 환경 (오늘 설치하며 익숙해집니다)
ChatCoworkClaude Code
AI가 일하는 곳대화창클라우드 컨테이너내 PC 터미널
내 파일 접근업로드한 파일만연동 폴더 읽기/쓰기폴더 직접 읽기/쓰기/실행
프로그램 실행—클라우드에서 실행내 PC에서 실행 (서버 가동)
어울리는 작업 길이분 단위 왕복시간 단위 자율 작업세션 단위 개발 작업
대표 작업질문·초안·요약수집·분석·문서 파이프라인백엔드·자동화 스크립트
한 줄 기억법 — Chat은 묻는 곳, Cowork는 맡기는 곳, Code는 (내 컴퓨터에서) 돌리는 곳.
2

주차별 작업대 배치 — 어디서 무엇을 하나

이 부트캠프는 주차마다 주 작업대가 정해져 있습니다. 무엇을 만드는지가 아니라 만든 것이 어디에 있어야 하는지가 기준입니다.

2주차 (이번 주) ②크롤링 이론 → ③웹 스크래핑 → ④임베딩 추출 → ⑤판결문 지도 → ⑥계보도(선택)인터넷 수집 + 대량 API 호출 + 장시간 자율 작업 · 결과는 내 PC 폴더에 파일로 쌓임 · 동적 사이트는 크롬 확장 병용
COWORK
3주차 검색엔진 → RAG → Vercel 배포이번 주에 쌓은 파일을 재료로, 내 PC에서 검색 서버를 켜고 서비스로 세상에 내놓는다
CODE
4주차 MCP·시트 연동 → 스킬 → 자율 에이전트작업대들을 외부 도구와 연결하고, 절차를 파일로 남겨 AI가 스스로 움직이게 한다
CODE
그 사이사이 — 연구 아이디어 다듬기, 법리 질문, 결과 해석 토론짧은 왕복 대화 — 실행할 것이 없을 때는 여전히 Chat이 가장 빠릅니다
CHAT
2주차가 Cowork인 이유 — 오래 걸리고, 파일이 많이 나온다 판결문 수백 건 수집과 임베딩 API 호출은 시간 단위로 도는 자율 작업이고 산출물이 파일 수백 개입니다. Cowork는 클라우드에서 이 일을 돌리면서 결과를 연동해 둔 내 PC 폴더로 내려줍니다 — 그래서 3주차가 시작될 때 그 파일들이 이미 내 컴퓨터에 있습니다.
3주차부터 Code인 이유 — 서버는 내 컴퓨터에서 떠 있어야 한다 웹앱이 부를 서버는 브라우저와 같은 컴퓨터에서 계속 실행 중이어야 합니다(localhost). Cowork의 클라우드 컨테이너는 세션이 끝나면 사라지고 내 브라우저의 localhost가 아니므로, "터미널에서 서버를 켜고 유지하는" 일은 Claude Code의 영역입니다. API 키를 내 PC에만 두는 보안 구조와도 맞아떨어집니다. 그런데도 Claude Code를 이번 주에 미리 설치하는 이유는 두 가지 — 3주차 첫 실습에서 세팅에 시간을 쓰지 않고 바로 시작하기 위해서, 그리고 이번 주에도 파이썬 버전 확인 같은 가벼운 일에 한 번 써 보며 터미널과 미리 친해지기 위해서입니다.
설치 전에 알아둘 것 — 손발을 주는 일에는 위험이 따른다 지금부터 설치할 도구들은 내 파일을 읽고, 쓰고, 지우고, 인터넷으로 보낼 수 있습니다. 그만큼 파일 파괴·데이터 유출·프롬프트 인젝션(수집한 웹페이지 속에 숨은 지시문을 AI가 명령으로 착각하는 공격) 같은 위험이 따라옵니다. 그래서 이번 주 실습은 두 가지 습관 위에서 진행합니다 — ① 모든 작업은 전용 폴더 하나 안에서만 합니다. 다음 절에서 만들 폴더가 곧 울타리이며, 사고가 나도 피해가 그 폴더를 넘지 않습니다. ② 실행 승인 요청은 반드시 읽고 누릅니다. 습관적으로 Enter를 치는 순간 울타리를 내 손으로 여는 셈입니다. 위험이 발생하는 구조와 이를 OS 수준에서 막는 샌드박스의 원리는 4주차 1강에서 깊게 다룹니다.
3

설치 ① — Claude 데스크톱 앱 + 크롬 확장

이번 주(②~⑥) 전 과정에서 쓸 도구 두 개입니다. 데스크톱 앱은 Cowork를 켜고 내 PC 폴더를 연동하는 창구이고, 크롬 확장은 스크롤·클릭해야 내용이 나오는 동적 사이트를 수집할 때 씁니다. 둘 다 Pro 이상 구독 계정으로 로그인해 씁니다.

1
Claude 데스크톱 앱 설치

claude.ai/download에서 Windows / macOS 설치 파일을 받아 실행합니다. 설치 후 앱을 열고 1주차에 쓰던 같은 계정으로 로그인하세요 — 대화 기록과 프로젝트가 웹과 그대로 이어집니다.

2
작업 폴더 만들고 Cowork에 연동하기

이번 주 산출물이 전부 쌓일 폴더를 하나 만듭니다 (예: 바탕화면/week2). 데스크톱 앱에서 Cowork를 열고 이 폴더를 연동하면, Cowork가 클라우드에서 만든 파일이 내 PC의 이 폴더로 내려옵니다.

여기가 웹과 갈리는 지점 1주차 claude.ai에서는 결과물을 하나씩 내려받아야 했습니다. 폴더를 연동하면 수집한 CSV, 판결문 파일 수백 개, 임베딩 JSON 347개가 알아서 이 폴더에 저장됩니다. 3주차에 Claude Code가 열게 될 폴더도 바로 여기입니다.
3
Claude in Chrome (브라우저 확장) 설치

크롬 웹스토어에서 Claude for Chrome 확장을 설치하고, 툴바 아이콘을 눌러 같은 계정으로 로그인합니다. 이 확장은 내 브라우저가 이미 화면에 그려낸 내용을 읽기 때문에, 자바스크립트로 나중에 채워지는 목록이나 "더보기" 버튼 뒤의 내용까지 수집할 수 있습니다 (왜 필요한지는 ②번 자료(크롤링 이론)에서 다룹니다).

4
연동 확인 — 파일이 정말 내 PC에 떨어지는지
💬 Cowork 첫 프롬프트
연동한 폴더에 test.csv 파일을 만들어줘. 컬럼은 순번, 제목, 메모 3개이고
아무 예시 행 3개만 넣어줘.

탐색기(또는 Finder)에서 그 폴더를 열어 test.csv가 보이면 준비 완료입니다. 확인했으면 지워도 됩니다.

4

설치 ② — Claude Code (3주차부터 본격 사용)

설치는 터미널에 명령 한 줄입니다. Pro 이상 구독 계정이면 추가 비용 없이 로그인해서 씁니다. 3주차 첫 실습(검색 서버 켜기)에서 바로 쓸 수 있도록 지금 미리 끝내 두고, 이번 주에도 파이썬 확인 같은 가벼운 일에 한 번 써 봅니다.

1
터미널 열기

Windows: 시작 메뉴에서 PowerShell 검색 → 실행. macOS: Spotlight(⌘+Space)에서 터미널 검색 → 실행.

2
설치 명령 실행
Windows (PowerShell)
irm https://claude.ai/install.ps1 | iex
macOS / Linux
curl -fsSL https://claude.ai/install.sh | bash

터미널이 낯설면 대안도 있습니다 — 방금 설치한 Claude 데스크톱 앱 안에도 Code가 들어 있어 그래픽 화면으로 같은 일을 할 수 있습니다.

3
설치 확인 + 로그인
확인
claude --version

버전 번호가 나오면 성공. §3에서 Cowork에 연동해 둔 그 폴더로 이동해 claude를 입력하면 브라우저가 열리며 로그인(구독 계정)합니다. 문제가 있으면 claude doctor가 진단해 줍니다.

4
첫 대화 — 3주차 검색 서버 실습 사전 점검
💬 첫 프롬프트
파이썬이 설치되어 있는지 버전을 확인해줘. 없다면 설치 방법을 안내해줘.

Cowork와 똑같이 한국어로 대화하면 됩니다 — 다른 점은 명령이 내 컴퓨터에서 실행된다는 것뿐입니다. 실행 전에 항상 허락을 구하므로, 무엇을 하려는지 읽고 승인하세요.

5
샌드박스 켜기 — 4주차 1강에서 원리를 배울 울타리 미리 두르기
Claude Code 안에서 입력
/sandbox

패널이 열리면 Mode 탭에서 자동 승인 또는 일반 권한 모드를 고릅니다. macOS는 바로 켜지고, Linux·WSL2는 bubblewrap·socat이 필요하다는 안내가 뜨면 패널이 알려주는 대로 설치한 뒤 다시 실행하세요. Windows는 WSL2 안에서 Claude Code를 실행해야 샌드박스가 적용됩니다 — 네이티브 Windows에서는 지원되지 않고, 이 경우 권한 승인 프롬프트가 유일한 방어선이 되니 승인을 더 신중히 읽어야 합니다.

내 PC에서 실행된다 = 책임도 내 PC 샌드박스는 사고의 범위를 좁혀 줄 뿐입니다. Claude Code는 울타리 밖으로 나가야 하는 명령·파일 삭제·새 도메인 접속에 확인을 요청하는데, 이때 승인 버튼을 습관적으로 누르면 울타리를 내가 여는 셈이 됩니다. 내용을 읽고 승인하세요. 중요한 폴더는 백업 후 실습하시고요.
5

마무리 체크리스트

  • Chat은 묻는 곳, Cowork는 맡기는 곳, Code는 내 컴퓨터에서 돌리는 곳
  • 구분 기준은 기능 목록이 아니라 "AI의 손발이 어디에 있는가"
  • 1주차는 웹(claude.ai)이면 충분했지만, 2주차는 산출물이 파일이라 작업대가 내 PC로 내려온다
  • 2주차는 전 과정 Cowork(데스크톱 앱 + 폴더 연동 + 크롬 확장), 3주차부터 Claude Code(검색엔진·RAG·배포), 4주차는 연동과 자율 에이전트
  • 동적 사이트 수집에는 크롬 확장 — 브라우저가 이미 그려낸 화면을 읽는다
  • AI에게 내 컴퓨터의 손발을 주는 일에는 위험이 따른다 — 작업은 전용 폴더 하나 안에서만, 실행 승인은 읽고 누른다
  • 위험의 구조와 샌드박스의 원리는 4주차 1강에서 깊게 다룬다
다음 강의 — 이론: 크롤링설치를 마쳤으니 수집으로 들어갑니다. 웹에서 무엇을 모을 수 있는지, 법적·윤리적 경계는 어디인지, 정적/동적 사이트는 무엇이 다른지 — 실습(③) 전에 판단 기준부터 세웁니다.
미리 준비OpenRouter 계정과 API 키, 소액 크레딧 충전(④번 자료 임베딩용). 판결문 347건 전체 임베딩 비용이 약 2센트 수준이니 부담 없습니다.
