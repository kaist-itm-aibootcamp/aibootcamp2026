WEEK 2 · STEP 4 — 임베딩 추출

판결문 347건을 숫자로 —
임베딩 추출 파이프라인

수집한 판결문을 "읽는" 대신 "재는" 방법을 배웁니다. 텍스트를 의미의 좌표(임베딩)로 바꾸면 검색·지도·군집 분석이 가능해집니다. 이 페이지의 수치와 사례는 실제 판결문 코퍼스에 이 파이프라인을 돌린 기록입니다.

1

임베딩이란 — 비정형 데이터를 숫자로 요약하기

판결문 한 건은 평균 8,500자짜리 비정형 텍스트입니다. 통계도, 지도도, 유사도 계산도 텍스트 그대로는 불가능합니다. 임베딩은 이 문제를 푸는 도구입니다.

재료 — 앞 강의에서 수집한 895건 중 347건 앞 강의(웹 스크래핑)에서 "직장 내 괴롭힘"이 언급된 지방법원 판결 895건의 목록을 수집했습니다. 그중 본문 전문을 확보하고 분석 대상(직장 내 괴롭힘 민사 손해배상)으로 확정한 347건이 이 페이지부터 계속 쓰이는 코퍼스입니다. 수집한 전부를 쓰는 것이 아니라 분석 목적에 맞는 것만 추리는 단계가 수집과 분석 사이에 반드시 들어갑니다 — 여러분의 데이터에서도 마찬가지입니다.

먼저 seq-to-seq 모델부터

번역기를 생각해 보세요. 문장(단어의 시퀀스)이 들어가면 번역문(다른 시퀀스)이 나옵니다. 내부는 두 부분입니다 — 입력 문장을 읽어 의미를 압축한 숫자 뭉치로 만드는 인코더, 그 숫자 뭉치를 풀어 출력 문장을 만드는 디코더.

seq-to-seq에서 임베딩이 나오는 자리

인코더가 만든 "의미 요약 숫자"만 떼어 저장한 것이 임베딩입니다
한 문장 정의 임베딩 = 복잡한 비정형 데이터(텍스트)를 의미가 보존되도록 수치로 요약한 것. 비슷한 내용의 글은 비슷한 숫자가 되므로, 숫자 사이의 거리가 곧 의미의 거리가 됩니다. 모든 판결문에 GPS 좌표를 붙인다고 생각하면 됩니다 — 쟁점이 비슷하면 이웃 동네.
2

OpenRouter — 임베딩을 뽑는 가장 편한 창구

임베딩 모델을 내 PC에서 직접 돌릴 수도 있지만, 비개발자에게는 API 호출이 압도적으로 편합니다. 그리고 여러 회사의 모델을 한곳에서 쓰게 해주는 중개소가 OpenRouter입니다.

🔀
하나의 키, 수백 개 모델OpenAI·Google·Qwen 등 여러 회사 모델을 API 키 하나로 호출. 모델명 문자열만 바꾸면 모델이 바뀝니다.
💳
선불 크레딧openrouter.ai 가입 → 소액 충전(몇 달러면 충분) → Keys 메뉴에서 API 키 발급. 쓴 만큼만 차감됩니다.
🧾
투명한 사용 내역대시보드에서 호출 1건 단위로 토큰·비용이 조회됩니다 — 뒤에서 이 내역이 검증 도구로도 쓰입니다(§4).

임베딩 모델 고르기 — 컨텍스트 길이가 핵심

이번 코퍼스 실측: 347건 평균 8,492자, 최대 41,374자. 8,000자를 넘는 판결문이 절반 가까이라, 컨텍스트가 8K 토큰인 모델은 절반이 잘립니다(한국어는 글자당 토큰 소모가 커서 더 심함). 실제 조회된 선택지:

모델 (OpenRouter 슬러그)컨텍스트단가비고
qwen/qwen3-embedding-8b32K$0.01/M선택 — 길이·가격 모두 유리
google/gemini-embedding-00120K$0.15/M
openai/text-embedding-3-large8K$0.13/M장문 판결문 절반이 잘림
baai/bge-m38K$0.01/M
비용 감각 — 판결문 347건 전체(본문+개요)를 임베딩하는 데 든 비용은 약 2센트였습니다. "API는 비쌀 것"이라는 걱정은 임베딩에서는 대체로 기우입니다.
3

Cowork 파이프라인 — PC 폴더 연동과 API 키

코드를 한 줄도 쓰지 않고, Cowork에 요청 하나로 전체 파이프라인을 맡깁니다. 핵심은 API 키를 안전하게 전달하는 방법입니다.

① PC 폴더 연동Cowork에서 판결문이 있는 로컬 폴더를 연결
→
② 키 파일 저장연동 폴더에 openrouterkey.txt (키 한 줄) 저장
→
③ 프롬프트"키를 읽어 임베딩을 뽑고 JSON으로 저장해줘"
→
④ 클라우드 실행Cowork가 키를 환경변수로만 읽어 API 호출
→
⑤ 결과 동기화판결문별 JSON 347개가 PC 폴더로 돌아옴
💬 실제 사용한 요청 (수업용으로 다듬음) 
수집된 판결문 본문의 임베딩을 OpenRouter API로 뽑으려 한다.
연동 폴더에 openrouterkey.txt 파일을 저장해 두었다. 키를 읽어 API 호출을 하고,
판결문별로 JSON 파일을 저장해줘. JSON에는 metadata.csv의 기본 서지 정보 +
본문 전체 임베딩 + 요약문 + 요약문 임베딩을 넣으면 될 것 같다.
키 보안 — 반드시 확인할 것 키는 환경변수로만 읽게 하고, 화면·로그·산출물 어디에도 출력하지 말 것을 명시하세요(Cowork도 같은 원칙으로 동작합니다). 작업이 끝나면 평문 키 파일이 폴더에 남아 있다는 사실을 잊지 마세요 — 폴더를 공유·백업하기 전에 키 파일을 빼두어야 합니다. 실제 작업에서도 AI가 이 점을 마지막에 상기시켜 주었습니다.
구조 이해 — 내 PC 쪽에는 네트워크 실행 권한이 없으므로, 실제 HTTP 호출은 Cowork의 클라우드 컨테이너에서 일어나고 완성된 JSON이 PC 폴더로 돌아오는 구조입니다. "어디서 무엇이 실행되는가"는 민감 데이터를 다룰 때 꼭 확인해야 할 질문입니다.
4

실전 기록 — 요청 한 줄 뒤에서 실제로 일어난 일들

위의 짧은 요청에 대해 AI가 스스로 수행한 검증과, 사용자가 던진 확인 질문의 기록입니다. AI에게 일을 맡기는 법과 결과를 믿는 법을 동시에 보여줍니다.

1
AI가 모델명부터 바로잡았다

사용자는 "chatgpt-oss-embedding 모델로"라고 요청했지만 그런 모델은 실존하지 않았습니다. AI는 그대로 진행하는 대신 OpenRouter의 실제 임베딩 모델 목록과 단가를 조회해 표로 제시하고 선택을 물었습니다. 교훈: 이름·수치가 애매하면 AI에게 실존 확인부터 시키세요.

2
데이터를 실측한 뒤 모델을 골랐다

코퍼스 전체 길이를 실측(평균 8,492자, 8천자 초과 다수)해 컨텍스트 8K 모델을 배제하고 32K 모델을 권장했습니다. 최장 판결문(24,250토큰)을 실제로 보내 절단 없이 과금되는지까지 확인했습니다.

3
시험 5건 → 검증 → 본 배치

전량을 바로 돌리지 않고 5건으로 시험 실행 후 무결성을 검증했습니다 — 차원 4,096 동일, 벡터 정규화 확인, 본문 벡터가 자기 개요와 가장 가까운지(정합성) 확인. 통과 후 본 배치: 347건, 13.8분, 실패 0건, 비용 약 2센트.

4
사용자는 "과금 내역"으로 교차검증했다

사용자가 OpenRouter 대시보드에서 호출 이력이 353건임을 보고 물었습니다 — "본문과 요약을 따로 불렀으면 2배여야 하는 것 아닌가?" AI의 답: 본문+요약을 한 요청에 배열로 담아 판결당 1콜이며, 353 = 소통 확인 1 + 절단 검증 2 + 시험 5 + 본 배치 342 + 검색 스팟체크 3. 토큰 수도 로컬 계산과 1토큰 오차 없이 일치. 교훈: AI의 보고를 외부 기록(과금 내역)과 대조하면 가장 확실합니다.

5

산출물과 활용 — 검색, 지도, 군집

판결문 1건당 JSON 파일 1개(평균 181KB)가 만들어졌습니다. 안에는 서지 정보와 두 개의 벡터가 들어 있습니다.

활용 ① — 의미 검색: 키워드가 아니라 "논리"로 찾기

질의문도 같은 모델로 임베딩해 거리가 가까운 판결을 찾으면, 단어가 아니라 판시 논리가 검색됩니다. 실제 스팟체크:

실제 검색 결과 "업무상 적정범위를 넘지 않았다고 보아 괴롭힘을 부정한 사례"로 질의 → 1·2위가 정확히 그 논리로 기각된 원고패 판결. "사용자의 예견가능성" 질의 → 보고서에서 대표 사례로 인용했던 판결(카카오톡 근거로 예견가능성 인정)이 1위. 키워드 검색으로는 불가능한 결과입니다.

활용 ② — 2D 지도와 클러스터링

4,096차원 좌표를 2차원으로 압축(UMAP 등)하면 코퍼스 전체가 한 장의 지도가 됩니다. 가까운 점 = 비슷한 판결. 여기에 클러스터링을 적용하면 "비슷한 판결 무리"가 자동으로 묶입니다.

판결문 지도 개념도

개념 설명용 그림입니다 — 실제 지도는 실습에서 여러분이 직접 만듭니다
다음 강의와의 연결 — 이 지도를 실제로 그린 기록이 바로 다음 강의(클러스터링·차원축소·시각화)입니다. 그리고 활용 ①의 의미 검색은 3주차의 검색엔진 강의에서 "새 질의를 실시간으로 임베딩하려면 왜 백엔드가 필요한가"로 이어집니다.
6

마무리 체크리스트

  • 임베딩 = 시퀀스(비정형 텍스트)의 의미를 요약한 고정 길이 숫자 벡터
  • OpenRouter: 키 하나로 여러 모델 — 모델 선택은 컨텍스트 길이와 단가로, 실존 여부는 AI에게 확인시키기
  • 키는 연동 폴더에 파일로 — 환경변수로만 읽게 하고, 작업 후 평문 키 파일 정리
  • 전량 실행 전 시험 실행 → 무결성 검증, 완료 후 과금 내역으로 교차검증
  • 임베딩의 활용: 의미 검색 · 2D 지도 · 클러스터링
다음 강의 — 판결문 지도추출한 임베딩 347건을 실제로 활용해 봅니다 — 클러스터링으로 사건 유형을 찾고 차원축소로 2D 지도를 그리는 판결문 347건 지도로 이어집니다.
