WEEK 2 · STEP 2 — 이론: 크롤링

크롤링 — 웹의 공개 데이터를
연구 재료로 만드는 기술

①번 자료에서 작업대(Cowork)와 폴더 연동을 준비했습니다. 이제 그 폴더에 무엇을 채울지 정할 차례입니다. 이 강의는 실습에 들어가기 전의 판단 기준을 세웁니다 — 웹에서 무엇을 모을 수 있는지, 어디까지 모아도 되는지(법적·윤리적 경계), 그리고 사이트의 구조에 따라 어떤 도구가 필요한지(정적 vs 동적). 실제 수집은 다음 자료(③ 실습)에서 합니다.

1

크롤링이란 — 무엇을 모을 수 있나

크롤링(crawling)·스크래핑(scraping)은 웹페이지에 이미 공개되어 있는 정보를 구조화된 데이터(표·CSV·JSON)로 긁어 모으는 일입니다. 사람이 브라우저로 읽는 것을 프로그램이 대신 읽고, 흩어진 내용을 분석 가능한 형태로 정리합니다. 연구와 업무에서 쓰이는 대표적인 원천들:

📰
뉴스 기사 · 보도자료특정 이슈가 언제, 얼마나, 어떤 논조로 다뤄졌는지이슈 트렌드 분석
🛒
커머스 목록 · 상품 리뷰베스트셀러 순위, 가격 변동, 소비자 불만 키워드시장·소비자 분석
⚖️
판례 · 법령 · 특허판결문에서 반복되는 인정 요건, 유사 선행 특허요건 분석 · 선행 조사
💼
채용 공고직무별 요구 스킬, 연봉 범위, 채용 수요의 변화노동시장 분석
🎓
학술 초록 · 연구 동향특정 주제의 연구가 언제부터 급증했는지, 핵심 저자는 누구인지문헌 지형 파악
💬
커뮤니티 · 앱 리뷰사용자 여론, 반복되는 불만, 경쟁 제품과의 비교 담론여론 · VOC 분석
이번 주에 실제로 해 볼 것 다음 자료(③ 실습)에서 온라인 서점의 경제·경영 베스트셀러를 성별×연령대 조합별로 소량(239권) 수집해 "세대·성별에 따라 어떤 책을 읽는가?"에 데이터로 답해 봅니다. 그리고 같은 방법을 판결문 895건에 적용한 연구용 분석 사례까지 봅니다. 데이터가 바뀌어도 원리는 같습니다 — 공개된 페이지를, 구조화된 형태로, 필요한 만큼만.
2

법적·윤리적 경계

기술적으로 "긁을 수 있다"와 법적으로 "긁어도 된다"는 다른 문제입니다. 수집을 시작하기 전에 세 가지를 확인하세요.

① 페이월(paywall) 뒤의 콘텐츠 — 하지 마세요

원칙적 금지 구독·결제·로그인 장벽 뒤에 있는 콘텐츠(유료 기사, 구독형 DB, 전자책 등)의 자동 수집은 거의 예외 없이 이용약관에서 금지되어 있고, 접근 제한을 우회하는 행위 자체가 별도의 법적 문제(기술적 보호조치 침해, 부정 접근 등)를 일으킬 수 있습니다. 페이월이 보이면 스크래핑 대상에서 제외하는 것을 기본값으로 삼으세요.

② 약관상 금지 = 항상 불법? — 그렇지는 않습니다

공개된 페이지라도 약관에 "자동화된 수집 금지" 조항이 있는 사이트가 많습니다. 다만 약관이 곧 최종 결론은 아닙니다. 공정이용(fair use)까지 금지하는 약관 조항은 무효로 판단될 수 있다는 것이 중요한 포인트입니다. 결국 핵심은 내 수집이 공정이용에 해당하는지 스스로 평가하는 것입니다.

공정이용 평가의 감각 오로지 비영리 목적 — 수업 과제나 연구 목적으로, 공개된 페이지를 소량 수집해 내부 분석에만 쓰는 경우라면 공정이용으로 인정될 가능성이 높습니다. 반대로 수집물을 상업적으로 재배포하거나, 원본 사이트를 대체하는 서비스를 만들거나, 대량 수집으로 서버에 부담을 주면 공정이용과 멀어집니다. 이번 주 실습(상업 서점의 공개 목록을 수업 목적으로 소량 수집·내부 분석)이 바로 이 평가를 통과하는 전형적인 사례입니다.

③ 그 밖의 기본 수칙

  • robots.txt 확인 — 사이트 주소 뒤에 /robots.txt를 붙이면 수집 허용/금지 경로가 나옵니다. Cowork에 "이 사이트 robots.txt 확인해줘"라고 요청하면 됩니다.
  • 서버 배려 — 요청 사이에 간격을 두고, 필요한 만큼만 수집하세요. (이번 주 실습도 그룹별 Top 20, 분석에 필요한 소량만 수집합니다)
  • 개인정보 — 닉네임·프로필·작성자 정보도 개인정보일 수 있습니다. 분석에 불필요하면 수집 단계에서 제외(익명화)하세요.
  • 출처 기록 — 수집 일시·URL·조건을 데이터와 함께 저장해 두면 연구 재현성과 인용 문제를 함께 해결합니다.
수업의 관점 — 이 부트캠프의 실습은 전부 "비영리·소량·내부 분석"의 범위 안에서 설계되어 있습니다. 각자 연구에 응용할 때도 이 세 단어를 기준으로 삼으세요. (본 자료는 일반적인 교육 안내이며, 구체적 사안에 대한 법률 자문이 아닙니다.)
3

정적 vs 동적 — 기술적 구분

수집 대상이 정해졌다면, 이제 그 사이트가 어떻게 만들어져 있는지를 봐야 합니다. 사이트의 구조에 따라 필요한 도구가 달라지기 때문입니다.

정적(static) 사이트는 주소(URL)만 요청하면 서버가 내용이 이미 담긴 HTML을 통째로 보내주는 사이트입니다. 반면 요즘 웹사이트 대부분은 동적(dynamic) 로딩 — 서버가 빈 껍데기 HTML만 먼저 주고, 실제 내용은 자바스크립트가 나중에 채워 넣는 방식 — 을 씁니다.

정적 — URL만으로 수집 가능

  • 주소만 바꿔도 원하는 목록이 그대로 열림 (예: 페이지 번호, 검색 조건이 URL에 드러남)
  • 정부·공공기관 게시판, 오래된 게시판형 사이트
  • Cowork에 URL 규칙만 알려주면 바로 수집 가능

동적 — 브라우저가 필요

  • 스크롤·클릭해야 내용이 나타남, URL은 그대로
  • SNS 피드, 쇼핑몰 리뷰 더보기, 지도, 로그인 화면
  • 브라우저 확장(Claude in Chrome)으로 수집
확인 방법 — 브라우저 주소창의 URL만 바꿔서(페이지 번호, 조건 등) 원하는 목록이 바로 열리면 정적으로 접근 가능. 스크롤하거나 버튼을 눌러야만 내용이 나타나고 URL은 그대로라면 동적입니다.

동적 사이트의 해법 — Claude in Chrome (브라우저 확장)

①번 자료에서 설치한 크롬 확장이 여기서 등장합니다. 확장을 쓰면 AI가 내 브라우저가 이미 렌더링을 끝낸 화면을 읽습니다. 자바스크립트가 채워 넣은 내용, 스크롤로 불러온 목록, (내 계정으로) 로그인된 화면까지 — 사람 눈에 보이는 그대로를 대상으로 하므로 동적 로딩 문제가 사라집니다. 스크롤과 클릭도 AI가 대신 수행합니다.

Cowork 단독 수집크롬 확장 수집
읽는 대상서버가 보내주는 HTML브라우저가 그려낸 최종 화면
맞는 사이트정적 — URL 규칙이 있는 목록동적 — 스크롤·클릭·로그인 화면
강점대량·반복 수집, 백그라운드 실행사람이 보는 것은 무엇이든 수집
유의점동적 내용은 비어 있을 수 있음내 계정·내 브라우저로 하는 일 — 책임도 내 계정에
로그인 화면 수집 시 주의 내 계정으로 보이는 화면은 편리한 만큼 책임도 내 계정에 귀속됩니다. §2의 원칙(페이월 금지, 비영리·소량, 개인정보 제외)은 브라우저 방식에서도 똑같이 적용됩니다.
4

마무리 체크리스트

  • 크롤링 = 공개된 웹 정보를 구조화된 데이터(표·CSV·JSON)로 모으는 일 — 대상 6유형과 분석 용도를 말할 수 있다
  • 페이월 콘텐츠는 수집하지 않는다 — 접근 제한 우회는 그 자체로 법적 문제
  • 약관의 수집 금지 조항이 최종 결론은 아니다 — 공정이용(비영리·소량·내부 분석) 관점에서 스스로 평가한다
  • robots.txt 확인, 서버 배려, 개인정보 제외, 출처 기록 — 네 가지 기본 수칙
  • 정적·동적 확인 방법: URL만 바꿔 열리면 정적, 스크롤·클릭이 필요하면 동적
  • 정적은 Cowork에 URL 규칙으로, 동적은 크롬 확장으로 — 도구 선택 기준이 생겼다
다음 강의 — 실습: Cowork로 웹 스크래핑오늘 세운 기준을 실제로 적용합니다. 정적 사이트(서점 베스트셀러)를 프롬프트 하나로 수집해 ①번 자료에서 연동한 폴더에 CSV로 저장하고, 바로 이어서 탐색적 분석(EDA)까지 해봅니다.
미리 생각해 오기내 연구·업무에서 모으고 싶은 데이터 하나를 골라 오늘 배운 기준으로 점검해 보세요 — 페이월은 없는가? 공정이용 범위인가? URL만 바꿔서 열리는가(정적), 스크롤이 필요한가(동적)?
